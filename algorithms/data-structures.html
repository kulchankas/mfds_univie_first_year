Heaps & priority queues EXAM 1 · 8 pts

Definition A binary min-heap is a nearly complete binary tree (all levels full except possibly the last, filled left-to-right) with the min-heap property: $A[\mathrm{parent}(i)]\le A[i]$ for every non-root $i$. The minimum is at the root. (Max-heap: reverse the inequality; used by heapsort.)

Array storage — level by level, left to right, in $A[1..n]$: $\mathrm{parent}(i)=\lfloor i/2\rfloor$, $\mathrm{left}(i)=2i$, $\mathrm{right}(i)=2i+1$; height $\lfloor\lg n\rfloor$. No pointers needed.

The full pseudocode of MIN-HEAPIFY (float down, $O(\lg n)$), BUILD-MIN-HEAP (bottom-up from $\lfloor n/2\rfloor$, $O(n)$) and MIN-HEAP-DECREASE-KEY (float up, $O(\lg n)$) is written out in the mock-exam model solution Q3 — that answer is the exam-ready version. Summary of the priority-queue interface:

OperationIdeaTime
MIN-HEAP-MINIMUMreturn $A[1]$$\Theta(1)$
MIN-HEAP-EXTRACT-MINsave $A[1]$; move $A[n]$ to root; shrink; MIN-HEAPIFY$(A,1)$$O(\lg n)$
MIN-HEAP-DECREASE-KEYlower key at $i$; swap upward while parent larger$O(\lg n)$
MIN-HEAP-INSERTappend key at end; float it up (insert $+\infty$, then decrease-key)$O(\lg n)$
BUILD-MIN-HEAPMIN-HEAPIFY internal nodes $\lfloor n/2\rfloor$ downto $1$$O(n)$

Why BUILD-MIN-HEAP is $O(n)$, not $O(n\lg n)$: a heapify call at height $h$ costs $O(h)$, and at most $\lceil n/2^{h+1}\rceil$ nodes sit at height $h$; so the total is $\sum_{h=0}^{\lfloor\lg n\rfloor}\lceil n/2^{h+1}\rceil\,O(h)=O\!\big(n\sum_{h\ge0}h/2^h\big)=O(n)$ since $\sum h/2^h=2$.

Heapsort ($O(n\lg n)$, in place, not stable): BUILD-MAX-HEAP; then for $i=n$ downto $2$: swap $A[1]\leftrightarrow A[i]$, shrink the heap, MAX-HEAPIFY$(A,1)$.

Exam tip The three index formulas + heap property + "leaves start at $\lfloor n/2\rfloor{+}1$" answer most heap sub-questions. Know DECREASE-KEY goes up, HEAPIFY goes down.

Binary search trees EXAM 1 · with RBT

Definition A binary search tree is a binary tree of key-carrying nodes satisfying the BST property: for every node $x$, all keys in $x$'s left subtree are $\le x.key$ and all keys in $x$'s right subtree are $\ge x.key$.

Storage — linked nodes with fields key, left, right, p (parent) and satellite data; missing children are NIL; the tree is reached via T.root. An inorder walk (left, node, right) prints the keys in sorted order in $\Theta(n)$.

TREE-SEARCH(x, k)                     TREE-INSERT(T, z)
  while x ≠ NIL and k ≠ x.key:          y = NIL;  x = T.root
    if k < x.key: x = x.left            while x ≠ NIL:            // walk down
    else: x = x.right                     y = x
  return x                              if z.key < x.key: x = x.left
                                        else: x = x.right
TREE-MINIMUM(x)                       z.p = y
  while x.left ≠ NIL: x = x.left      if y == NIL: T.root = z
  return x                            else if z.key < y.key: y.left = z
                                      else: y.right = z
  • Successor of $x$: if $x.right\ne$ NIL, it's TREE-MINIMUM$(x.right)$; else walk up until you arrive from a left child.
  • Delete $z$: no children → remove; one child → splice it in; two children → replace $z$ by its successor (which has no left child), transplanting subtrees.
  • All operations run in $O(h)$, $h$ = height. Randomly built: expected $h=O(\lg n)$; worst case (sorted insertions) $h=n-1$ — the whole point of balanced trees.

Red-black trees EXAM 1 · 6 pts

Definition — the five red-black properties A red-black tree is a BST with a color bit per node such that: (1) every node is red or black; (2) the root is black; (3) every leaf (NIL sentinel) is black; (4) a red node has only black children; (5) for each node, all simple paths down to descendant leaves contain the same number of black nodes (the node's black-height $bh$).
Height lemma (CLRS 13.1) A red-black tree with $n$ internal nodes has height $h\le 2\lg(n+1)$. Sketch: induction shows the subtree at $x$ has $\ge 2^{bh(x)}-1$ internal nodes; property (4) forces $bh(\text{root})\ge h/2$ (at least half of any root-leaf path is black); so $n\ge 2^{h/2}-1$.

Hence SEARCH / MIN / MAX / SUCCESSOR / INSERT / DELETE all run in $O(\lg n)$ worst case.

Rotations — the $O(1)$ rebalancing primitive, preserving the BST property:

        LEFT-ROTATE(T,x)                 RIGHT-ROTATE(T,y)
      x                y                      y                x
     / \              / \                    / \              / \
    α   y    ⟶      x   γ                  x   γ    ⟶      α   y
       / \          / \                    / \                  / \
      β   γ        α   β                  α   β                β   γ

Insertion = BST-insert $z$ + color it red (so property 5 never breaks; only 4 — or 2 — can) + RB-INSERT-FIXUP. Full pseudocode: mock exam, model solution Q4. The three fixup cases, with $z$'s uncle $y$ (shown for parent = left child; mirror otherwise; red, black):

Case 1 — uncle red: recolor, push up.
        C                    C  ← new z
       / \                  / \
      A   y      ⟶        A   y          (may loop again
       \                    \              two levels up)
        z                    z

Case 2 — uncle black, z inner ("triangle"): rotate parent → Case 3.
        C                      C
       / \                    / \
      A   y      ⟶          B   y        (LEFT-ROTATE at A;
       \                    /              old parent becomes z)
        B=z                A=z

Case 3 — uncle black, z outer ("line"): recolor + rotate grandparent. Done.
        C                      B
       / \                    / \
      B   y      ⟶          A   C        (RIGHT-ROTATE at C;
     /                              \      loop terminates)
    A=z                              y

Finally the root is recolored black. Cost: $O(\lg n)$, at most 2 rotations per insertion (Case 1 only recolors). Deletion is analogous (four fixup cases, ≤ 3 rotations) — know it exists and its cost; insertion is what exam 1 asked in detail.

Exam tip Recite the five properties in order — that alone was 1 pt. For fixup, the decision tree is: uncle red? → recolor. Uncle black? triangle → rotate parent; line → recolor + rotate grandparent.

AVL trees SHEET 8 · PROB 80

Definition An AVL tree is a binary search tree that is height balanced: for every node $x$, the heights of its two subtrees differ by at most 1. Each node stores an extra attribute $x.h$ = the height of the subtree rooted at $x$ (a leaf has $h=0$; by convention $\mathrm{NIL}.h=-1$).

Red-black trees and AVL trees solve the same problem — keeping a BST at $O(\lg n)$ height — with different bookkeeping. AVL keeps a tighter balance (so lookups are slightly faster) at the cost of more rotations on update. Problem 80 walks through the whole construction in four parts; here they are.

(a) Why the height is $O(\lg n)$

Turn the question around: what is the fewest nodes an AVL tree of height $h$ can have? Call it $N(h)$. To be as sparse as possible at height $h$, the root has one subtree of height $h-1$ and — by the balance rule, the smallest it may legally be — one of height $h-2$: $$N(0)=1,\qquad N(1)=2,\qquad N(h)=1+N(h-1)+N(h-2).$$ This is the Fibonacci recurrence with an offset. Indeed $N(h)=F_{h+3}-1$, where $F_1=F_2=1$ — check: $N(0)=F_3-1=1$, $N(1)=F_4-1=2$, $N(2)=1+2+1=4=F_5-1$. ✓ (The sheet's hint asks only for the weaker $N(h)\ge F_h$, which is enough.)

Now use $F_k=\Theta(\varphi^k)$ with $\varphi=\frac{1+\sqrt5}{2}$, precisely $F_k=\varphi^k/\sqrt5$ rounded. A tree with $n$ nodes and height $h$ has $n\ge N(h)=F_{h+3}-1$, so $$n+1\ \ge\ \frac{\varphi^{\,h+3}}{\sqrt5}\quad\Longrightarrow\quad h\ \le\ \log_\varphi\!\big(\sqrt5\,(n+1)\big)-3\ \approx\ 1.44\lg n .$$ Hence $h=O(\lg n)$. $\blacksquare$

Compare AVL guarantees $h\lesssim1.44\lg n$; a red-black tree only guarantees $h\le2\lg(n+1)$. That is the precise sense in which AVL is "more balanced" — and the same style of argument (minimum nodes at a given height) proves both.

(b) BALANCE — the four rotation cases

$\mathrm{BALANCE}(x)$ assumes both children of $x$ are already height-balanced and their heights differ by at most 2, and returns the root of the repaired subtree. Everything is decided by which side is heavy and then which grandchild is heavy — exactly the "line vs triangle" distinction from red-black insertion:

BALANCE(x)
  if x.left.h > x.right.h + 1:              // left-heavy
    if x.left.left.h ≥ x.left.right.h:      // Left-Left  ("line")
      x = RIGHT-ROTATE(x)
    else:                                   // Left-Right ("triangle")
      x.left = LEFT-ROTATE(x.left)
      x = RIGHT-ROTATE(x)
  else if x.right.h > x.left.h + 1:         // right-heavy (mirror)
    if x.right.right.h ≥ x.right.left.h:    // Right-Right
      x = LEFT-ROTATE(x)
    else:                                   // Right-Left
      x.right = RIGHT-ROTATE(x.right)
      x = LEFT-ROTATE(x)
  UPDATE-HEIGHT(x)
  return x

UPDATE-HEIGHT(x)                            // call after any rotation
  x.h = 1 + max(x.left.h, x.right.h)
Left-Left — one rotation            Left-Right — two rotations

      x  (h+2)                              x                      z
     / \                                   / \                    / \
   y     D   ── RIGHT-ROTATE(x) ─→       y     D   ──→  first   y     x
  / \                  y                / \            rotate  / \   / \
 z   C                / \              A   z           at y   A  C  D  …
/ \                  z   x                / \                        then
A  B                /|   |\              B   C                    RIGHT-ROTATE(x)
                   A B   C D

Left-Left is the "line" case: a single right rotation at $x$ lifts $y$ and fixes it. Left-Right is the "triangle": first left-rotate at $y$ to straighten it into a line, then right-rotate at $x$. The right-heavy cases are mirror images. At most 2 rotations per BALANCE call.

(c) AVL-INSERT

Insert as in a plain BST, then rebalance on the way back up the recursion — the recursive formulation makes this natural, because the return value re-attaches the (possibly rotated) subtree root to its parent:

AVL-INSERT(x, z)                            // returns the new subtree root
  if x == NIL:  return z                   // z.h = 0, z.left = z.right = NIL
  if z.key < x.key:
    x.left  = AVL-INSERT(x.left,  z);  x.left.p  = x
  else:
    x.right = AVL-INSERT(x.right, z);  x.right.p = x
  UPDATE-HEIGHT(x)
  return BALANCE(x)                         // repairs this level if it went off by 2

// top level:  T.root = AVL-INSERT(T.root, z);  T.root.p = NIL

(d) Why it is $O(\lg n)$ time and $O(\lg n)$ rotations

The descent visits one node per level, and by part (a) there are $O(\lg n)$ levels. On the way back up, each level costs $O(1)$: an UPDATE-HEIGHT plus a BALANCE that performs at most 2 rotations, each $O(1)$. So the total is $O(\lg n)$ time and $O(\lg n)$ rotations. $\blacksquare$

Sharper, and worth knowing For insertion the bound is actually $O(1)$ rotations, not $O(\lg n)$: the first rebalance restores the subtree to the height it had before the insert, so no ancestor can still be unbalanced and the loop stops. Deletion is the case that genuinely needs $O(\lg n)$ rotations, because a delete can shorten a subtree and cascade all the way to the root. The problem only asks for $O(\lg n)$, so proving the weaker bound is fine — but saying this earns credit.

Hash tables

Definition A hash table stores $n$ keys from a large universe $U$ in an array $T[0..m-1]$ via a hash function $h:U\to\{0,\dots,m-1\}$; $k$ lives in slot $h(k)$. When $|U|>m$, collisions ($h(k_1)=h(k_2)$) are unavoidable (pigeonhole) and must be resolved. Load factor: $\alpha=n/m$.

Direct addressing (the special case $U$ small): $T[k]$ stores key $k$ directly — $O(1)$ everything, but needs $|U|$ slots.

Collision resolution 1 — chaining

Slot $j$ holds a linked list of all keys hashing to $j$. INSERT: prepend, $O(1)$. SEARCH/DELETE: walk the chain. Under simple uniform hashing (each key equally likely in each slot): unsuccessful search $\Theta(1+\alpha)$ (Thm 11.1), successful search $\Theta(1+\alpha)$ (Thm 11.2) — both on the proofs page. With $n=O(m)$, all dictionary ops are expected $O(1)$.

Collision resolution 2 — open addressing

All keys live in the table itself ($\alpha\le 1$); probing follows a per-key probe sequence $\langle h(k,0),h(k,1),\dots,h(k,m-1)\rangle$ until an empty slot (insert) or the key (search) is found. Deletion is awkward (use DELETED markers). The schemes:

  • Linear probing: $h(k,i)=(h'(k)+i)\bmod m$ — simple, cache-friendly, suffers primary clustering (long occupied runs grow).
  • Quadratic probing: $h(k,i)=(h'(k)+c_1 i+c_2 i^2)\bmod m$ — avoids primary, has secondary clustering (equal $h'$ ⇒ identical sequences).
  • Double hashing: $h(k,i)=(h_1(k)+i\,h_2(k))\bmod m$ with $h_2(k)$ relatively prime to $m$ — closest to uniform hashing in practice.

Under uniform hashing: unsuccessful search $\le\frac{1}{1-\alpha}$ (Thm 11.6), successful search $\le\frac1\alpha\ln\frac{1}{1-\alpha}$ (Thm 11.8 — proof).

Hash functions

  • Division method: $h(k)=k\bmod m$; pick $m$ prime, away from powers of 2.
  • Multiplication method: $h(k)=\lfloor m(kA\bmod 1)\rfloor$ for constant $0<A<1$; $m$ can be a power of 2.
  • Universal hashing: choose $h$ at random from a family $\mathcal H$ with $\Pr_{h\in\mathcal H}[h(x)=h(y)]\le 1/m$ for all $x\ne y$ — defeats adversarial inputs; e.g. $h_{ab}(k)=((ak+b)\bmod p)\bmod m$.
Exam tip A hashing "describe" question wants: the collision problem, chaining + $\alpha$ + the $\Theta(1+\alpha)$ theorems, the three probing schemes with their clustering issues, and one hash-function construction. That's the full-marks checklist.

B-trees

Definition (minimum degree $t\ge 2$) A B-tree is a balanced search tree whose nodes hold many keys: every node $x$ stores $x.n$ keys in sorted order and (if internal) $x.n+1$ children, with the search-tree property that the keys of child $c_i$ lie between $x$'s $(i{-}1)$-st and $i$-th key. Constraints: every non-root node has $t-1\le x.n\le 2t-1$ keys (root: $\ge 1$), and all leaves have the same depth $h$.

Height bound: $n\ge 1$ keys force $h\le\log_t\frac{n+1}{2}$ — logarithmic with a huge base. That's the point: B-trees are built for disk/secondary storage, where reading a node = one expensive disk page access; a fat node ($t$ in the thousands) makes the tree 2–3 levels deep for billions of keys.

  • SEARCH: in each node, scan/binary-search the $\le 2t-1$ keys, descend into one child — $O(t\log_t n)$ CPU, $O(\log_t n)$ disk reads.
  • INSERT: descend to a leaf, but split every full node on the way down (a full node's median key moves up into the parent, the rest splits into two $(t-1)$-key nodes); then insert into the non-full leaf. $O(t\log_t n)$.
  • DELETE: symmetric — ensure every node visited has $\ge t$ keys by borrowing from or merging siblings. $O(t\log_t n)$.
Exam tip Lead with why (disk accesses dominate; minimize tree height by fattening nodes), then the definition with the $t-1\,/\,2t-1$ bounds and equal leaf depth, then splitting on the way down.

Stacks, queues & linked lists

  • Stack — LIFO. Array implementation with top index: PUSH$(S,x)$: S.top++; S[S.top]=x; POP$(S)$: return S[S.top--]; underflow/overflow checks. Both $O(1)$.
  • Queue — FIFO. Circular array with head/tail: ENQUEUE writes at tail and advances it mod $m$; DEQUEUE reads at head and advances it. Both $O(1)$.
  • Linked list — nodes with prev/next: SEARCH $\Theta(n)$; INSERT/DELETE $O(1)$ given a pointer to the position. A sentinel node removes boundary special-cases.
  • Stacks/queues are how DFS (stack/recursion) and BFS (queue) get their orders — a common side-question.

Dynamic programming

The two hallmarks Optimal substructure — an optimal solution contains optimal solutions to subproblems. Overlapping subproblems — the naive recursion solves the same subproblems repeatedly, so caching pays. DP = recursion + a table.
  • Top-down with memoization: write the recursion, cache each result on first computation.
  • Bottom-up: order subproblems by size and fill the table iteratively.
  • Runtime $=$ (number of subproblems) $\times$ (choices per subproblem).

Rod cutting (sheets 9–10): price $p_i$ for a rod of length $i$; maximize revenue for length $n$: $$r_0=0,\qquad r_n=\max_{1\le i\le n}\big(p_i+r_{n-i}\big)$$ — $n$ subproblems × $O(n)$ choices $=O(n^2)$; reconstruct the cuts by also storing the argmax. Optimal BST: expected-cost-minimal search tree over keys with access probabilities; interval subproblems $e[i,j]=\min_{i\le r\le j}\big(e[i,r-1]+e[r+1,j]+w(i,j)\big)$, $O(n^3)$. Same interval pattern as matrix-chain multiplication.

Greedy algorithms

The two ingredients Greedy-choice property — some globally optimal solution is consistent with the locally best first choice (proved by an exchange argument). Optimal substructure — after the greedy choice, what remains is the same kind of problem. Greedy = DP where one choice is provably safe without solving subproblems first.
  • Activity selection — always take the earliest-finishing compatible activity: Theorem 15.1.
  • Huffman codes — always merge the two rarest symbols: Lemmas 15.2/15.3 + Theorem 15.4, fully worked on the mock exam (Q5). EXAM 1 · 10 pts
  • Contrast with DP in one sentence: DP tries all choices and takes the best; greedy commits to one choice and must prove it safe.

Graphs & traversal SHEET 11 · PROB 101–102

Definition A directed graph is $\Gamma=(V,E)$ with $E\subseteq V\times V$; edges are ordered pairs, so $(i,j)\neq(j,i)$. A path of length $k$ is a vertex sequence $v_0v_1\dots v_k$ with $(v_{i-1},v_i)\in E$; it is a cycle if $v_0=v_k$. A directed graph with no cycles is a DAG.

BFS and DFS

Both visit every vertex and edge once, so both run in $\Theta(V+E)$ on adjacency lists. The only real difference is the container holding the frontier — and that choice is what makes them behave completely differently.

BFS(G, s)                                   // queue → shortest paths by edge count
  for each u ∈ V − {s}: u.d = ∞; u.π = NIL
  s.d = 0;  s.π = NIL;  Q = {s}
  while Q ≠ ∅:
    u = DEQUEUE(Q)
    for each v ∈ Adj[u]:
      if v.d == ∞:                          // undiscovered
        v.d = u.d + 1;  v.π = u;  ENQUEUE(Q, v)

DFS(G)                                      // stack/recursion → timestamps
  time = 0
  for each u ∈ V: u.colour = WHITE; u.π = NIL
  for each u ∈ V: if u.colour == WHITE: DFS-VISIT(G, u)

DFS-VISIT(G, u)
  time = time + 1;  u.d = time;  u.colour = GRAY      // discovered
  for each v ∈ Adj[u]:
    if v.colour == WHITE: v.π = u; DFS-VISIT(G, v)
  u.colour = BLACK
  time = time + 1;  u.f = time                        // finished

BFS computes shortest-path distances in unweighted graphs ($u.d$ = fewest edges from $s$). DFS computes two timestamps per vertex: $u.d$ when it is discovered (goes grey) and $u.f$ when its whole subtree is done (goes black). Every vertex satisfies $u.d<u.f$, and the $2|V|$ timestamps are all distinct.

Parenthesis theorem For any two vertices $u,v$, exactly one of these holds:
  • the intervals $[u.d,u.f]$ and $[v.d,v.f]$ are disjoint, and neither is a descendant of the other;
  • $[u.d,u.f]\subset[v.d,v.f]$, and $u$ is a descendant of $v$ in the DFS forest;
  • $[v.d,v.f]\subset[u.d,u.f]$, and $v$ is a descendant of $u$.
Think of writing "$($" at discovery and "$)$" at finish: the result is a well-formed parenthesis string. Intervals never partially overlap.

Edge classification PROB 102

DFS sorts every edge $(u,v)$ into exactly one of four classes, and the class is readable straight off the timestamps — which is exactly what problem 102 asks you to prove:

ClassMeaningTimestamp testColour of $v$ when explored
Tree$v$ first discovered via this edge$u.d<v.d<v.f<u.f$WHITE
Forward$v$ a non-child descendant of $u$BLACK
Back$v$ an ancestor of $u$ (or $u$ itself)$v.d\le u.d<u.f\le v.f$GRAY
Crosseverything else — across subtrees or trees$v.d<v.f<u.d<u.f$BLACK

Why the tests work. If $(u,v)$ is a tree or forward edge then $v$ is a proper descendant of $u$, so by the parenthesis theorem $v$'s interval is strictly inside $u$'s: $u.d<v.d<v.f<u.f$. If it is a back edge then $u$ is a descendant of $v$ (or $u=v$ on a self-loop), giving the reverse containment $v.d\le u.d<u.f\le v.f$. Otherwise neither is a descendant, so the intervals are disjoint — and since we explore $(u,v)$ while $u$ is grey, $v$ must already have finished, so $v$'s interval lies entirely to the left: $v.d<v.f<u.d<u.f$. The three cases are mutually exclusive and exhaustive. $\blacksquare$

Two facts worth memorising (1) A directed graph is acyclic iff DFS finds no back edge — that is how you test for a DAG in $O(V+E)$. (2) In an undirected graph only tree and back edges occur; forward and cross edges are impossible (whichever endpoint is reached first becomes the ancestor).

Topological sort

Run DFS and output vertices in decreasing finish time (i.e. push each onto a stack as it finishes). $\Theta(V+E)$. Correctness: for any edge $(u,v)$ in a DAG, $v$ finishes before $u$ — if $v$ were unfinished when we explored $(u,v)$ it would be grey, making $(u,v)$ a back edge and the graph cyclic. So decreasing $f$ respects every edge.

Longest path in a DAG PROB 86

Longest simple path is NP-hard in general — but on a DAG every path is automatically simple, and DP works. Let $L(v)$ be the weight of the heaviest path from $v$ to $t$: $$L(t)=0,\qquad L(v)=\max_{(v,w)\in E}\big(w_{(v,w)}+L(w)\big),$$ evaluated in reverse topological order so each $L(w)$ is ready when needed. Read the path off by following the argmax from $s$. Each edge is relaxed once: $\Theta(V+E)$.

Diameter of a tree PROB 101

The diameter is $\max_{u,v}\delta(u,v)$. Two clean $O(V)$ methods:

  • Double BFS. BFS from any vertex $r$; let $a$ be a farthest vertex found. BFS again from $a$; the greatest distance found is the diameter. Why: the farthest vertex from any start is always an endpoint of some longest path — if it were not, one could splice a longer path, contradiction. (This needs the graph to be a tree; it is false on general graphs.)
  • One DFS. For each node return its height; the longest path through a node $v$ is $1+h(\text{tallest child})+1+h(\text{2nd tallest child})$. Track the running maximum over all $v$. One post-order pass, $O(V)$.
