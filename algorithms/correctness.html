Correctness & loop invariants

This was question 1 on the first-date exam, worth 8 points — and sheet 1 spends six of its seventeen problems on it. It is also the most learnable thing on the syllabus: there is one template, it never changes, and the marks are awarded for following it visibly.

What "correct" actually means

The two halves An algorithm is correct for a given precondition/postcondition pair when:
  • Partial correctness — if it terminates, the output satisfies the postcondition.
  • Termination — it does in fact terminate on every legal input.
Total correctness = partial correctness + termination. A loop invariant proves the first. Termination needs a separate argument, and it is a separate mark.
For a sorting algorithm, "correct" is three claims Sheet 1 says it explicitly — your invariant must carry three properties. A sort is correct when:
  1. it terminates;
  2. the output is sorted (non-decreasing);
  3. the output is a permutation of the input — same elements, same multiplicities.
Drop clause 3 and your proof also "proves" an algorithm that overwrites the array with zeros: that output is perfectly sorted. This is the single most commonly dropped mark in the whole course, and it was literally exam 1, question 1(a).

The three obligations

The template — memorise the shape, not the words Pick a property $P(\cdot)$ of the program state, indexed by the loop variable. Then prove:
ObligationWhat you showInduction analogue
Initialization$P$ holds just before the first iterationbase case
Maintenanceif $P$ holds at the start of an iteration, it still holds at the start of the nextinductive step
Terminationthe loop stops, and $P$ combined with the exit condition gives the postconditioncashing in the conclusion
The one insight A loop invariant is an induction proof wearing work clothes. Initialization is the base case, maintenance is the inductive step. The only genuinely new part is termination — and that is where students go wrong, because they treat it as a formality. It is not: termination is where you substitute the exit value of the loop variable into the invariant and read off the thing you were asked to prove.
Say "at the start of each iteration" Always state the invariant as holding at the start of an iteration, before the body runs. Then "the start of the next iteration" is unambiguous, and at termination the loop variable has its exit value (e.g. $n+1$ for for i = 1 to n), which is exactly what makes the final substitution work.

Making the invariant strong enough

Almost every failed attempt fails the same way: the invariant is true but useless. Two rules.

Rule 1 — it must imply the postcondition at exit Work backwards. Write down what you want at the end, then ask: "what statement, with the loop variable set to its exit value, becomes exactly this?" That is your invariant.

For a sort with for i = 1 to n, you want "$A[1..n]$ is a sorted permutation of the input". Setting $i=n+1$ in "$A[1..i-1]$ is a sorted permutation of the original $A[1..i-1]$" gives precisely that. ✓
Rule 2 — it must survive the body If maintenance will not go through, the invariant is too weak and must be strengthened — you add a clause. This feels backwards (you are making the thing you must prove harder) but it is standard: a stronger hypothesis is also a stronger tool in the inductive step.

Selection sort is the classic case. "$A[1..i-1]$ is sorted" alone does not survive: nothing stops the algorithm from placing a small element after a large one later. You must add "and every element of $A[1..i-1]$ is $\le$ every element of $A[i..n]$".
Diagnosing a stuck maintenance step If you cannot finish maintenance, ask what fact you wished you had. That wished-for fact is the missing clause. Add it, re-check initialization (usually still trivial), and continue.

Worked — SUM-ARRAY PROB 2

The gentlest possible example, and the right one to practise the shape on.

SUM-ARRAY(A, n)
    s = 0
    for i = 1 to n
        s = s + A[i]
    return s
Invariant At the start of each iteration of the for loop with index $i$, $$s=\sum_{k=1}^{i-1}A[k].$$

Initialization Before the first iteration $i=1$, so the claim is $s=\sum_{k=1}^{0}A[k]$, the empty sum, which is $0$. The code sets $s=0$. ✓

Maintenance Suppose the invariant holds at the start of the iteration with index $i$, so $s=\sum_{k=1}^{i-1}A[k]$. The body executes $s\gets s+A[i]$, giving $$s_{\text{new}}=\sum_{k=1}^{i-1}A[k]+A[i]=\sum_{k=1}^{i}A[k],$$ which is exactly the invariant with $i$ replaced by $i+1$ — the start of the next iteration. ✓

Termination The loop exits when $i=n+1$. Substituting into the invariant: $$s=\sum_{k=1}^{n}A[k],$$ which is the value returned. That is the postcondition. ∎

Termination (that it stops) $i$ starts at 1, increases by 1 each iteration and the loop runs while $i\le n$; so after exactly $n$ iterations $i=n+1$ and the loop ends.

Note the empty-sum move Initialization worked because $\sum_{k=1}^{0}=0$ by convention. Getting the boundary right — empty sum, empty subarray, empty set — is what makes initialization trivial instead of awkward. If initialization looks hard, your indices are probably off by one.

Worked — linear search PROB 3–4

Read the sheet's output spec carefully Problem 3 is not "return NIL if absent". The sheet asks for: an index $i$ with $x=A[i]$; if $x$ does not appear, the largest index $i$ with $A[i]<x$; and $0$ if no such index exists. The input is strictly increasing. So this is a predecessor search, and the invariant has to be built for that postcondition — see Rule 1. The full solution, with the Julia version, is on the Sheet 1 page.
The trick One rule covers both hit and miss: walk forward while the next element is still $\le x$. On a hit you stop exactly on $x$; on a miss you stop on its predecessor; if even $A[1]>x$ you never move and return $0$.
LINEAR-SEARCH(A, n, x)
    i = 0
    while i < n and A[i+1] <= x
        i = i + 1
    return i
Invariant At the start of each iteration of the while loop: $$0\le i\le n\quad\text{and}\quad A[k]\le x\ \text{ for every }1\le k\le i.$$

Initialization $i=0$: the bound holds, and $A[1..0]$ is empty so the second clause is vacuous. ✓

Maintenance The body runs only when $i<n$ and $A[i+1]\le x$. Afterwards $i$ has become $i+1\le n$, and the guard just supplied the one missing fact $A[i+1]\le x$, so the property extends to the whole range $1..i+1$. ✓

Termination — two exits This is the part worth the marks, because each exit needs its own argument.

  • $i=n$. Everything is $\le x$, so $A[n]$ is the largest element and $A[n]\le x$ — returning $n$ is correct whether it is a hit or the predecessor. ✓
  • $A[i+1]>x$. Here sortedness does the work: every $k\ge i+1$ has $A[k]\ge A[i+1]>x$, so nothing beyond $i$ can be the answer. With the invariant covering $k\le i$: if $A[i]=x$ it is a hit; if $A[i]<x$ then $i$ is the largest such index; and if $i=0$ nothing is $\le x$, so $0$ is right. ✓

The loop terminates The variant is $n-i$: a non-negative integer, strictly decreasing, and the guard $i<n$ fails at $0$.

Worst case $\Theta(n)$, attained whenever $x\ge A[n]$; best case $\Theta(1)$. Note that sortedness buys correctness of the early exit, not a better worst case — for that you need binary search, $\Theta(\lg n)$.

Nested loops

The discipline Prove the inner loop first, as a self-contained invariant proof. Then use its termination conclusion as a single step inside the outer loop's maintenance.

Do not try to reason about both at once. The outer maintenance step is allowed to say "by the inner loop's termination, at this point $A[\dots]$ holds $\dots$" — that is what the inner proof was for.

Selection sort is the canonical two-loop example on sheet 1, and it is the closest sibling to the bubblesort question that actually appeared:

Selection sort — the two invariants PROB 5–7 Inner (finding the minimum of $A[i..n]$): at the start of each iteration with index $j$, $A[\mathit{min}]=\min\{A[i..j-1]\}$ and $i\le\mathit{min}\le j-1$.

Outer: at the start of each iteration with index $i$ — (a) $A[1..i-1]$ is sorted; (b) every element of $A[1..i-1]$ is $\le$ every element of $A[i..n]$; (c) $A[1..n]$ is a permutation of the input.

Clause (b) is the strengthening. Without it, at termination you know $A[1..n-1]$ is sorted but you cannot conclude that the final element belongs at the end — the proof has a hole exactly one element wide. The full write-up, with all three obligations for both loops, is paper C question 1.

The other two are already written out Bubblesort — the actual exam question, worked with grader notes on the mock exam page. Insertion sort — the likeliest rotation, worked in full on the proofs page ①, and again as paper B question 1. Between those and selection sort above you have all four sorting invariants the course can reasonably ask for.

Termination measures

The recipe To prove a loop terminates, exhibit a variant: a quantity $\mu$ taking values in $\mathbb{N}$ (or any well-founded order) such that
  1. $\mu$ strictly decreases on every iteration, and
  2. the loop guard fails once $\mu$ reaches its floor.
There is no infinite strictly decreasing sequence of naturals, so the loop must stop.
LoopVariant $\mu$
for i = 1 to n$n-i+1$ — trivial, but say it
while j > 0 and A[j] > key (insertion sort)$j$ — decremented every pass, bounded below by the guard
while low <= high (binary search)$\mathit{high}-\mathit{low}+1$ — at least halves each time
Euclid's while b != 0$b$ — strictly decreasing since $a\bmod b<b$
A counted for loop still needs one sentence It is one line — "$i$ increases by 1 each iteration and the loop runs while $i\le n$, so it ends after $n$ iterations" — and it is worth a mark. Write it. The place termination genuinely bites is a while loop whose guard depends on data, like the inner loop of insertion sort.

Recursive correctness — strong induction

The recursive template A recursive procedure has no loop, so there is no invariant. Use strong induction on the input size $n$:
  1. Base case — the procedure is correct on the smallest inputs it handles without recursing.
  2. Inductive step — assume the procedure is correct on all inputs of size $<n$ (this is why it must be strong induction: the recursive calls need not be on size $n-1$), then show the combination step turns those correct sub-results into a correct result for size $n$.
  3. Termination — every recursive call is on a strictly smaller input, and the base case is reachable.
The correspondence Loop invariant and strong induction are the same proof in two syntaxes: initialization ↔ base case, maintenance ↔ inductive step, termination ↔ the recursion bottoming out. If the exam gives you recursive pseudocode, do not try to invent a loop invariant — reach for induction on $n$.

Worked — stooge sort PROB 51

Sheet 5 asks for correctness and a recurrence in one problem — very exam-shaped, and the correctness half is genuinely non-obvious.

STOOGE-SORT(A, i, j)
    if A[i] > A[j]
        swap A[i] and A[j]
    if i + 1 >= j
        return
    k = floor((j - i + 1) / 3)
    STOOGE-SORT(A, i,     j - k)    // first two-thirds
    STOOGE-SORT(A, i + k, j    )    // last two-thirds
    STOOGE-SORT(A, i,     j - k)    // first two-thirds again

Write $n=j-i+1$ for the length of the segment and $k=\lfloor n/3\rfloor$.

Base case If $n\le2$ the procedure performs the compare-and-swap and returns (the guard i+1 >= j holds). One comparison sorts a segment of length 1 or 2. ✓

Inductive step Let $n\ge3$ and assume STOOGE-SORT correctly sorts every segment of length $<n$. Each recursive call is on a segment of length $n-k<n$, so the hypothesis applies to all three.

Claim: after the first call, the $k$ largest elements of the segment all lie in $A[i+k..j]$ — the region the second call will sort.

  • The first call sorts $A[i..j-k]$. Any of the top $k$ elements that started there is now among the last $k$ positions of that range, i.e. in $A[j-2k+1..j-k]$.
  • That range sits inside $A[i+k..j]$ provided $j-2k+1\ge i+k$, i.e. $n\ge3k$ — true because $k=\lfloor n/3\rfloor$.
  • Any of the top $k$ elements that started in $A[j-k+1..j]$ was never touched, and that range is also inside $A[i+k..j]$.

So after the second call, which sorts $A[i+k..j]$, those $k$ largest elements occupy the final $k$ positions $A[j-k+1..j]$ in sorted order — and they are the $k$ largest of the whole segment, hence they are in their final positions.

What remains, $A[i..j-k]$, therefore contains exactly the $n-k$ smallest elements. The third call sorts that range, and by the induction hypothesis it does so correctly. The whole segment is now sorted. ∎

Termination Each call recurses on length $n-k=n-\lfloor n/3\rfloor$, which is strictly less than $n$ for $n\ge2$, and the base case catches $n\le2$.

The recurrence half Each call makes three recursive calls on segments of size $\approx\tfrac23n$ plus $\Theta(1)$ work: $$T(n)=3\,T\!\left(\tfrac{2n}{3}\right)+\Theta(1).$$ Master theorem with $a=3$, $b=\tfrac32$: watershed $n^{\log_{3/2}3}\approx n^{2.7095}$. Since $f(n)=\Theta(1)=O(n^{\log_{3/2}3-\varepsilon})$, this is case 1: $$T(n)=\Theta\!\left(n^{\log_{1.5}3}\right)\approx\Theta(n^{2.71}).$$ Worse than bubblesort — the point of the exercise is that a correct algorithm can still be terrible.

Writing it in the exam

The skeleton — fill in the blanks
  1. "Loop invariant: at the start of each iteration of the ⟨which⟩ loop with index ⟨var⟩, ⟨property⟩." — for a sort, remember the permutation clause.
  2. "Initialization." Set the loop variable to its initial value, show the property is (usually vacuously) true.
  3. "Maintenance." Assume it at the start of iteration ⟨var⟩; walk through what the body does; conclude it holds for ⟨var⟩ + 1. If there is an inner loop, invoke its termination result here.
  4. "Termination." Give the exit value of the loop variable, substitute it into the invariant, and state that the result is the postcondition.
  5. "The loop terminates because ⟨variant⟩ strictly decreases and is bounded below."
Five labelled paragraphs. Graders look for the labels — writing them makes partial credit easy to award even if a detail is wrong.
Budget Q1 was 8 points in a 90-minute, 40-point paper, so roughly 16 minutes. That is comfortable for this template once you have written it three or four times. Practise on SUM-ARRAY until the shape is automatic, then do selection sort cold.

Traps

TrapReality
Invariant says only "$A[1..i-1]$ is sorted"Also needs the permutation clause. Without it the proof is compatible with an algorithm that destroys data. Caps you around 5/8.
Termination treated as a formalityIt is where you substitute the exit value and derive the postcondition. Skipping it means you have proved nothing about the final state.
Proving "the invariant holds at the end of the body"State it at the start of an iteration. Otherwise the exit value of the loop variable does not line up and termination gets messy.
Selection sort without the "$\le$ everything after" clauseMaintenance goes through, but termination cannot place the last element. The hole is invisible unless you check it.
One invariant for a nested loopTwo loops, two invariants. Prove the inner one first and cite it in the outer maintenance step.
Inventing a loop invariant for recursive codeUse strong induction on the input size instead.
"Terminates because it's a for loop"Fine — but write the sentence. It is a mark.
Ordinary induction for a recursion that isn't on $n-1$Stooge sort recurses on $\tfrac23n$. You need strong induction ("correct for all sizes $<n$").
