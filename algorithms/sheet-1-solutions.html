What the table is really teaching Compare the 1 µs and 1000 years columns — a factor of $3\times10^{22}$ more time:
  • $f(n)=n$: $n$ goes from $10^{3}$ to $3\times10^{19}$ — the same factor.
  • $f(n)=n^{2}$: only the square root of that factor.
  • $f(n)=2^{n}$: from $n\approx9$ to $n\approx64$. Twenty-two orders of magnitude of extra compute buys you 55 more elements.
  • $f(n)=n!$: from $n=6$ to $n=21$.
That is the whole argument for caring about asymptotics: for exponential algorithms, hardware is irrelevant. Only a better algorithm helps.

2SUM-ARRAY, by loop invariant

ProblemProve SUM ARRAY correct using a loop invariant.
1: procedure SUM_ARRAY
2:     sum = 0
3:     for i = 1 to n do
4:         sum = sum + A[i]
5:     end for
6: end procedure
InvariantAt the start of each iteration of the for loop with index $i$, $$\mathit{sum}=\sum_{k=1}^{i-1}A[k].$$

Initialization Before the first iteration $i=1$, so the claim reads $\mathit{sum}=\sum_{k=1}^{0}A[k]$ — the empty sum, which is $0$. Line 2 sets $\mathit{sum}=0$. ✓

Maintenance Assume $\mathit{sum}=\sum_{k=1}^{i-1}A[k]$ at the start of iteration $i$. Line 4 gives $$\mathit{sum}_{\text{new}}=\sum_{k=1}^{i-1}A[k]+A[i]=\sum_{k=1}^{i}A[k],$$ which is the invariant with $i$ replaced by $i+1$ — exactly the statement at the start of the next iteration. ✓

Termination The loop ends with $i=n+1$. Substituting, $$\mathit{sum}=\sum_{k=1}^{n}A[k],$$ which is the required output. ∎ Correct

That it terminates $i$ starts at $1$, increases by $1$ per iteration, and the loop runs while $i\le n$; after exactly $n$ iterations $i=n+1$ and it stops.

Why initialization was painless Because $\sum_{k=1}^{0}=0$ by convention. If your initialization step looks awkward, your indices are off by one — restate the invariant over $A[1..i-1]$ rather than $A[1..i]$.

3Linear search on a sorted array

ProblemInput: a sorted sequence $a_1<a_2<\dots<a_n$ in an array $A$, and a value $x$. Output: an index $i$ with $x=A[i]$; if $x$ does not appear in $A$, the largest index $i$ with $A[i]<x$; if no such index exists, $0$. Write pseudocode for linear search, and implement it in Julia.
Read the output spec twice This is not "return NIL if absent". It is a predecessor search: on a miss you must return the position of the largest element still below $x$. Note also that the input is strictly increasing, so there are no duplicates — which is what makes "the" answer unique.
The trick Both cases — hit and miss — are covered by a single rule: walk forward while the next element is still $\le x$. On a hit you stop exactly on $x$; on a miss you stop on its predecessor; if even $A[1]>x$ you never move and return $0$.
LINEAR-SEARCH(A, n, x)
    i = 0
    while i < n and A[i+1] <= x
        i = i + 1
    return i

Trace the three cases:

  • $x=A[j]$. The guard holds for every step up to $i=j$. At $i=j$ the test $A[j+1]\le x$ fails, because $A[j+1]>A[j]=x$ by strict increase. Return $j$. ✓
  • $x$ absent, some element below it. Equality never occurs, so the guard is $A[i+1]<x$; the loop stops at the largest $i$ with $A[i]<x$. ✓
  • $x<A[1]$. The first test fails immediately, $i=0$ is returned. ✓

In Julia

function linear_search(A::Vector{T}, x::T) where T
    i = 0
    while i < length(A) && A[i+1] <= x
        i += 1
    end
    return i          # 0 means "x is smaller than everything"
end

(Julia is 1-indexed, so the pseudocode carries over unchanged. && short-circuits, which is what keeps A[i+1] in bounds.)

4Correctness of that search, and its worst case

ProblemProve your algorithm from Exercise 3 correct with a loop invariant. Make sure your loop invariant fulfils the three necessary properties. Give the worst-case asymptotic running time.
InvariantAt the start of each iteration of the while loop: $$0\le i\le n\quad\text{and}\quad A[k]\le x\ \text{ for every }1\le k\le i.$$

Initialization $i=0$: the bound $0\le0\le n$ holds, and the range $A[1..0]$ is empty, so the second clause is vacuously true. ✓

Maintenance The body runs only when the guard holds, i.e. $i<n$ and $A[i+1]\le x$. Afterwards $i$ has become $i+1$, so $i+1\le n$ keeps the first clause. For the second: by hypothesis $A[k]\le x$ for all $k\le i$, and the guard just gave $A[i+1]\le x$; hence $A[k]\le x$ for all $k\le i+1$. ✓

Termination The loop exits in one of two ways.

  • $i=n$. The invariant gives $A[k]\le x$ for all $k$, so $A[n]$ is the largest element and it is $\le x$. If $A[n]=x$ then $n$ is a correct "found" index; otherwise $A[n]<x$ and $n$ is the largest index with $A[k]<x$. Either way returning $n$ is correct. ✓
  • $A[i+1]>x$. Here sortedness does the work: $A$ is increasing, so $A[k]\ge A[i+1]>x$ for every $k\ge i+1$ — nothing beyond $i$ can be the answer. Combined with the invariant ($A[k]\le x$ for $k\le i$):
    • if $i\ge1$ and $A[i]=x$, returning $i$ is a correct hit;
    • if $i\ge1$ and $A[i]<x$, then $i$ is the largest index with $A[i]<x$; ✓
    • if $i=0$, no element is $\le x$, so returning $0$ is correct. ✓

∎ Correct

The loop terminates The variant is $n-i$: it is a non-negative integer, strictly decreases each iteration (since $i$ increases by 1), and the guard $i<n$ fails once it reaches $0$.

The "three necessary properties" The sheet's phrase refers to initialization, maintenance and termination — all three proved above. Note that termination here genuinely earns its keep: the loop has two exits, and each needs its own argument. Do not merge them.

Worst case Every iteration is $\Theta(1)$ and the loop runs at most $n$ times, which is attained whenever $x\ge A[n]$. So the worst-case running time is $$\Theta(n)\quad\text{— in particular } O(n).$$ The best case is $\Theta(1)$ ($x<A[1]$). Note that the sortedness buys correctness of the early exit, but not a better worst case — for that you would need binary search, $\Theta(\lg n)$.

5Selection sort — pseudocode

ProblemFind the smallest element of $A[1:n]$ and exchange it with the first; then the smallest of $A[2:n]$ and exchange with the second; and so on. Write pseudocode and implement it in Julia.
SELECTION-SORT(A, n)
    for i = 1 to n - 1
        min = i
        for j = i + 1 to n
            if A[j] < A[min]
                min = j
        swap A[i] and A[min]
function selection_sort!(A::Vector)
    n = length(A)
    for i in 1:n-1
        m = i
        for j in i+1:n
            if A[j] < A[m]
                m = j
            end
        end
        A[i], A[m] = A[m], A[i]
    end
    return A
end
Why the outer loop stops at $n-1$ When $i=n$ the unsorted part $A[n:n]$ is a single element which, by the invariant below, is already $\ge$ everything before it. The iteration would compare nothing and swap $A[n]$ with itself — harmless but pointless.

6Selection sort — invariant and proof

ProblemFind a loop invariant for selection sort and prove your assumption.

Two loops, so two invariants. Prove the inner one first and use its conclusion as a single step of the outer maintenance.

Inner invariant (the j loop) At the start of each iteration with index $j$: $\;A[\mathit{min}]=\min\{A[i],\dots,A[j-1]\}\;$ and $\;i\le\mathit{min}\le j-1$.

Initialization $j=i+1$ and $\mathit{min}=i$: the set is $\{A[i]\}$, whose minimum is $A[i]=A[\mathit{min}]$. ✓

Maintenance If $A[j]<A[\mathit{min}]$ the body sets $\mathit{min}=j$, and then $A[\mathit{min}]=A[j]=\min\{A[i..j]\}$. Otherwise $A[\mathit{min}]\le A[j]$, so $A[\mathit{min}]$ is still the minimum of the enlarged range $A[i..j]$. Either way the claim holds for $j+1$. ✓

Termination $j=n+1$, so $A[\mathit{min}]=\min\{A[i..n]\}$: the inner loop finds the index of a smallest element of the unsorted suffix. ✓

Outer invariant (the i loop) At the start of each iteration with index $i$: (a) $A[1..i-1]$ is sorted in non-decreasing order; (b) every element of $A[1..i-1]$ is $\le$ every element of $A[i..n]$; (c) $A[1..n]$ is a permutation of the original array.
Clause (b) is the whole difficulty With only (a) you can carry out maintenance and still fail at termination: knowing "$A[1..n-1]$ is sorted" says nothing about whether $A[n]$ belongs at the end. Clause (b) is what closes that gap. This is the standard strengthening move — you make the invariant harder to prove precisely so that it becomes strong enough to use.

Initialization $i=1$: $A[1..0]$ is empty, so (a) and (b) hold vacuously, and (c) holds since nothing has been modified. ✓

Maintenance By the inner loop's termination, $A[\mathit{min}]$ is a smallest element of $A[i..n]$. The body swaps it into position $i$.

  • (c) survives: a swap permutes the array. ✓
  • (b) survives: the new $A[i]$ came from $A[i..n]$, so by the old (b) it is $\ge$ everything in $A[1..i-1]$; and it was the minimum of $A[i..n]$, so it is $\le$ everything left in $A[i+1..n]$. ✓
  • (a) survives: $A[1..i-1]$ was sorted and the new $A[i]$ is $\ge$ all of it, so $A[1..i]$ is sorted. ✓

All three hold for $i+1$. ✓

Termination The loop ends with $i=n$. By (a), $A[1..n-1]$ is sorted; by (b), $A[n]\ge$ every earlier element. Hence $A[1..n]$ is sorted, and by (c) it is a permutation of the input — which is exactly the definition of a correct sort. ∎ Correct

7Selection sort — best and worst case

ProblemDetermine best- and worst-case running times, using $O$, $\Omega$ or $\Theta$, whichever fits best.

Count the comparisons For a fixed $i$ the inner loop runs from $j=i+1$ to $n$, i.e. $n-i$ times. Summing over $i=1,\dots,n-1$: $$\sum_{i=1}^{n-1}(n-i)=\sum_{m=1}^{n-1}m=\frac{n(n-1)}{2}.$$

The point of the exercise That count does not depend on the input at all — the loops are counted for loops with no early exit. The comparison count is $\frac{n(n-1)}{2}$ on every input, and the algorithm performs exactly $n-1$ swaps. Therefore $$T_{\text{best}}(n)=T_{\text{worst}}(n)=\Theta(n^{2}),$$ and since best and worst coincide we may simply say the running time is $\Theta(n^{2})$ — no $O$/$\Omega$ hedging needed.
Contrast with insertion sort Insertion sort's inner while loop can exit early, so it is $\Theta(n)$ on an already-sorted array and $\Theta(n^{2})$ in the worst case. Selection sort has no such escape — that is the answer the question is fishing for. Its one advantage is the swap count: $n-1$, versus up to $\Theta(n^{2})$ moves for insertion sort.

8Induction on $n=2^{k}$

ProblemShow by induction that for $n=2^{k}$, $k\ge1$, the solution of $$T(n)=\begin{cases}2 & n=2\\ 2T\!\left(\frac n2\right)+n & n>2\end{cases}$$ is $T(n)=n\lg n$.

Induct on $k$; write $n=2^{k}$ so the claim is $T(2^{k})=2^{k}k$.

Base case $k=1$ $T(2)=2$ by definition, and $2\lg2=2\cdot1=2$. ✓

Inductive step Assume $T(2^{k})=2^{k}k$ for some $k\ge1$. Then $2^{k+1}>2$, so the second branch applies: $$T(2^{k+1})=2\,T\!\left(2^{k}\right)+2^{k+1}=2\cdot2^{k}k+2^{k+1}=2^{k+1}k+2^{k+1}=2^{k+1}(k+1).$$ With $n=2^{k+1}$ this reads $T(n)=n\lg n$, the claim for $k+1$. ✓

By induction $T(n)=n\lg n$ for every $n=2^{k}$, $k\ge1$. ∎ $T(n)=n\lg n$

Check with small values $T(4)=2T(2)+4=8=4\lg4$ ✓ and $T(8)=2T(4)+8=24=8\lg8$ ✓. Thirty seconds of arithmetic that catches an algebra slip.

9Landau symbol drills

Problem(a) Express $123n^{2}+345n-148$ as $\Theta$ of a simple expression. (b) Is $2^{n+1}=O(2^{n})$? (c) Is $2^{2n}=O(2^{n})$? (d) Is $2^{n}=O(2^{2n})$? (e) Is $2^{n+1}=o(2^{n})$? (f) Is $2^{n}=o(2^{2n})$?

(a) $\Theta(n^{2})$. Upper: for $n\ge1$, $$123n^{2}+345n-148\le123n^{2}+345n^{2}=468n^{2}.$$ Lower: for $n\ge1$, $345n-148\ge197>0$, so the expression is $\ge123n^{2}$. Witnesses $c_1=123$, $c_2=468$, $n_0=1$.

(b) Yes. $2^{n+1}=2\cdot2^{n}$, so take $c=2$, $n_0=1$.

(c) No. $2^{2n}=(2^{n})^{2}$. If $2^{2n}\le c\,2^{n}$ for all large $n$, dividing gives $2^{n}\le c$ — impossible for a constant $c$, since $2^{n}\to\infty$.

(d) Yes. $2^{n}\le2^{2n}$ for all $n\ge0$, so $c=1$, $n_0=0$.

(e) No. Little-o requires the ratio to tend to $0$, but $2^{n+1}/2^{n}=2$ for every $n$. Formally: $o$ demands the bound for every $c>0$, and it fails for e.g. $c=1$.

(f) Yes. $2^{n}/2^{2n}=2^{-n}\to0$.

The lesson of (b) vs (c) A constant added to the exponent is a constant factor and disappears inside $O$. A constant multiplying the exponent is a change of base and does not: $2^{2n}=4^{n}$. This shows up again in every recurrence you will meet.

10$\Theta$ is transitive

ProblemAssume $f=\Theta(g)$ and $g=\Theta(h)$. Show $f=\Theta(h)$.

By definition there are constants $c_1,c_2>0$ and $n_1$ with $$c_1g(n)\le f(n)\le c_2g(n)\qquad\text{for all }n\ge n_1,$$ and constants $d_1,d_2>0$ and $n_2$ with $$d_1h(n)\le g(n)\le d_2h(n)\qquad\text{for all }n\ge n_2.$$

Let $n_0=\max(n_1,n_2)$ and take any $n\ge n_0$. Chaining the upper bounds (legal because $c_2>0$ and the functions are eventually non-negative): $$f(n)\le c_2\,g(n)\le c_2d_2\,h(n),$$ and chaining the lower bounds: $$f(n)\ge c_1\,g(n)\ge c_1d_1\,h(n).$$ So $c_1d_1\,h(n)\le f(n)\le c_2d_2\,h(n)$ for all $n\ge n_0$, with $c_1d_1>0$ and $c_2d_2>0$. That is exactly $f=\Theta(h)$. ∎

11$\Omega$ plus $\omega$

ProblemProve that $f=\Omega(h)$ and $g=\omega(k)$ imply $f+g=\Omega(h+k)$.
Main idea $\omega$ is stronger than $\Omega$, so the second hypothesis gives you a lower bound too — with a constant of your choosing. Pick $1$, add the two bounds, and take the smaller constant.

From $f=\Omega(h)$: there are $c>0$ and $n_1$ with $f(n)\ge c\,h(n)$ for $n\ge n_1$.

From $g=\omega(k)$: for every constant $c'>0$ there is an $n$ beyond which $g(n)>c'k(n)$. Apply this with $c'=1$: there is $n_2$ with $g(n)>k(n)$ for all $n\ge n_2$.

Now set $n_0=\max(n_1,n_2)$ and $c''=\min(c,1)>0$. For $n\ge n_0$: $$f(n)+g(n)\;\ge\;c\,h(n)+k(n)\;\ge\;c''h(n)+c''k(n)\;=\;c''\big(h(n)+k(n)\big).$$ So $f+g=\Omega(h+k)$. ∎

(As everywhere in this course, the functions are assumed eventually non-negative — otherwise "$\ge c''h$" cannot be weakened from "$\ge ch$".)

12$O$ composed with $o$

ProblemLet $f=O(g)$ and $g=o(h)$. Prove $f=o(h)$.
Main idea $o$ requires the bound for every constant, so the proof must start "let $a>0$ be arbitrary". The trick is to feed $a/c$ into the $o$ hypothesis, so that the $c$ from the $O$ hypothesis cancels.

From $f=O(g)$: fix $c>0$ and $n_1$ with $0\le f(n)\le c\,g(n)$ for $n\ge n_1$.

Let $a>0$ be arbitrary. Since $g=o(h)$, the definition applies to the positive constant $a/c$: there is $n_2$ with $0\le g(n)<\dfrac{a}{c}\,h(n)$ for all $n\ge n_2$.

For $n\ge\max(n_1,n_2)$ we may chain them: $$0\le f(n)\le c\,g(n)<c\cdot\frac{a}{c}\,h(n)=a\,h(n).$$ Since $a>0$ was arbitrary, $f=o(h)$. ∎

13Three consequences of Stirling

ProblemUse $\displaystyle n!=\sqrt{2\pi n}\left(\frac ne\right)^{n}\!\left(1+\Theta\!\left(\frac1n\right)\right)$ to show (a) $n!=o(n^{n})$, (b) $n!=\omega(2^{n})$, (c) $\lg(n!)=\Theta(n\lg n)$.

Write $S(n)=\sqrt{2\pi n}\left(1+\Theta(1/n)\right)$ for the sub-exponential factor; note $S(n)=\Theta(\sqrt n)$.

(a) $n!=o(n^{n})$. Divide: $$\frac{n!}{n^{n}}=S(n)\cdot\frac{(n/e)^{n}}{n^{n}}=S(n)\cdot e^{-n}=\Theta(\sqrt n)\,e^{-n}\;\longrightarrow\;0,$$ because $e^{-n}$ decays exponentially and $\sqrt n$ only grows polynomially. A ratio tending to $0$ is precisely little-o. ✓

(b) $n!=\omega(2^{n})$. Divide the other way: $$\frac{n!}{2^{n}}=S(n)\cdot\frac{(n/e)^{n}}{2^{n}}=S(n)\left(\frac{n}{2e}\right)^{n}.$$ As soon as $n>2e\approx5.44$ the base $\frac{n}{2e}$ exceeds $1$ and keeps growing, so the ratio $\to\infty$. That is $\omega$. ✓

(c) $\lg(n!)=\Theta(n\lg n)$. Take logarithms: $$\lg(n!)=\underbrace{\tfrac12\lg(2\pi n)}_{\Theta(\lg n)}+\;n\lg\frac ne\;+\underbrace{\lg\!\left(1+\Theta(1/n)\right)}_{O(1)} = n\lg n-n\lg e+\Theta(\lg n).$$ The leading term is $n\lg n$ and everything else is $O(n)=o(n\lg n)$, so $\lg(n!)=\Theta(n\lg n)$. ✓ ∎

Why (c) matters more than the other two It is the engine of the $\Omega(n\lg n)$ comparison-sort lower bound: a decision tree must have $\ge n!$ leaves, a binary tree of height $h$ has $\le2^{h}$ leaves, so $h\ge\lg(n!)=\Omega(n\lg n)$. See Theorem 8.1.

15Substitution: $T(n)=4T(n/2)+n$

ProblemUse the substitution method to prove $T(n)=4T(n/2)+n$ implies $T(n)=\Theta(n^{2})$. Hint from the sheet: subtract a lower-order term.
Why the naive guess fails Try $T(n)\le cn^{2}$. Then $$T(n)\le4c\left(\frac n2\right)^{2}+n=cn^{2}+n,$$ which is bigger than $cn^{2}$ — the induction does not close. The residue $+n$ has nowhere to go. That is exactly the situation the hint is describing.

Upper bound — strengthen the hypothesis Guess instead $$T(n)\le cn^{2}-dn\qquad\text{for constants }c,d>0.$$ This is a stronger claim, which is the point: the extra $-dn$ gives the induction something to spend. Assume it for $n/2$: $$T(n)\le4\left[c\left(\frac n2\right)^{2}-d\,\frac n2\right]+n=cn^{2}-2dn+n=cn^{2}-dn-\big(d-1\big)n .$$ This is $\le cn^{2}-dn$ exactly when $(d-1)n\ge0$, i.e. $d\ge1$. Choose $d=1$, and choose $c$ large enough that the bound holds on the base cases. Hence $T(n)=O(n^{2})$.

Lower bound Guess $T(n)\ge cn^{2}$. Then $$T(n)\ge4c\left(\frac n2\right)^{2}+n=cn^{2}+n\ge cn^{2},$$ which closes immediately — here the leftover $+n$ works for us. So $T(n)=\Omega(n^{2})$.

Both bounds give $T(n)=\Theta(n^{2})$. ∎

Sanity check with the Master Theorem $a=4$, $b=2$, watershed $n^{\log_2 4}=n^{2}$; $f(n)=n=O(n^{2-\varepsilon})$ with $\varepsilon=1$, so case 1 gives $\Theta(n^{2})$ ✓. The exercise wants substitution, but always check your answer this way — it costs ten seconds.
Remember the asymmetry Subtracting a lower-order term helps the upper bound and is unnecessary for the lower one. The general rule: if the induction leaves a positive residue you cannot absorb, strengthen by subtracting a term of the residue's order.

16Recursion tree: $T(n)=4T(n/3)+n$

ProblemSketch the recursion tree, derive a guess for an asymptotic upper bound, then prove the guess by induction.

The tree At depth $i$ there are $4^{i}$ nodes, each with a subproblem of size $n/3^{i}$ and hence local cost $n/3^{i}$. So the cost of an entire level is $$4^{i}\cdot\frac{n}{3^{i}}=n\left(\frac43\right)^{i}.$$ Levels get more expensive as you descend, since $4/3>1$ — the leaves dominate. The tree has depth $\log_3 n$, so the total is $$\sum_{i=0}^{\log_3 n}n\left(\frac43\right)^{i}=n\cdot\Theta\!\left(\left(\tfrac43\right)^{\log_3 n}\right)=n\cdot\Theta\!\left(n^{\log_3(4/3)}\right)=\Theta\!\left(n^{1+\log_3 4-1}\right)=\Theta\!\left(n^{\log_3 4}\right),$$ using $\log_3(4/3)=\log_3 4-1$. Since $\log_3 4\approx1.2619$, the guess is $$T(n)=O\!\left(n^{\log_3 4}\right).$$

Proof by induction The same trap as problem 15 appears, so subtract a lower-order term from the start. Guess $$T(n)\le c\,n^{\log_3 4}-dn .$$ The key identity is $4\cdot\left(\tfrac13\right)^{\log_3 4}=4\cdot\tfrac14=1$, because $3^{\log_3 4}=4$. Assuming the bound for $n/3$: $$T(n)\le4\left[c\left(\frac n3\right)^{\log_3 4}-d\,\frac n3\right]+n = c\,n^{\log_3 4}-\frac{4d}{3}n+n = c\,n^{\log_3 4}-dn-\left(\frac d3-1\right)n .$$ This is $\le c\,n^{\log_3 4}-dn$ provided $\frac d3\ge1$, i.e. $d\ge3$. Take $d=3$ and $c$ large enough for the base cases. ∎ $T(n)=\Theta\!\left(n^{\log_3 4}\right)$

Cross-check Master theorem: $a=4$, $b=3$, watershed $n^{\log_3 4}\approx n^{1.26}$; $f(n)=n=O(n^{\log_3 4-\varepsilon})$ for small $\varepsilon$ — case 1 ✓. And note the contrast with problem 15: there the root dominated the leaves in cost per level? No — in both cases the leaves dominate, which is why both are case 1.

17Strassen by the Master Theorem

ProblemConsider the recursion for Strassen's matrix-multiplication algorithm. Using the Master Theorem, prove that its running time satisfies $T(n)=O(n^{\lg7})$.

The recurrence Strassen splits two $n\times n$ matrices into four $\frac n2\times\frac n2$ blocks and — this is the whole trick — computes the product with 7 recursive multiplications instead of the obvious 8, using $\Theta(n^{2})$ additions and subtractions to combine: $$T(n)=7\,T\!\left(\frac n2\right)+\Theta(n^{2}).$$

Apply the theorem Here $a=7$, $b=2$, $f(n)=\Theta(n^{2})$. The watershed function is $$n^{\log_b a}=n^{\log_2 7}=n^{\lg7},\qquad \lg7\approx2.807.$$

Compare $f$ with it: we need $f(n)=O\!\left(n^{\lg7-\varepsilon}\right)$ for some $\varepsilon>0$. Taking $\varepsilon=0.8$ gives $n^{\lg7-0.8}\approx n^{2.007}$, and indeed $n^{2}=O(n^{2.007})$. So $f$ is polynomially smaller than the watershed — this is case 1, and $$T(n)=\Theta\!\left(n^{\lg7}\right)=O\!\left(n^{\lg7}\right).\qquad\blacksquare$$

Why this is the famous example Ordinary block multiplication gives $T(n)=8T(n/2)+\Theta(n^{2})$, watershed $n^{\log_2 8}=n^{3}$ — case 1 again, so $\Theta(n^{3})$, no better than the schoolbook algorithm. Saving one of the eight multiplications drops the exponent from $3$ to $\lg7\approx2.807$. The entire gain is in $a$, not in $f$.
Say "polynomially smaller" and mean it Case 1 needs a genuine $\varepsilon>0$; it is not enough that $f$ is smaller. Exhibiting the $\varepsilon$ (as above) is worth a mark, and it is the habit that saves you on the recurrences where the gap is only logarithmic and the case fails — see drill group C.
