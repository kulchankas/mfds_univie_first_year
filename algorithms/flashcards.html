Define a binary min-heap — both the shape and the ordering condition.
A nearly complete binary tree (all levels full except possibly the last, filled left-to-right) with the min-heap property: $A[\mathrm{parent}(i)]\le A[i]$ for every non-root node. Consequence: the minimum is at the root $A[1]$.
Heap in an array $A[1..n]$: give the formulas for parent, left, right of index $i$, and the height of the heap.
$\mathrm{parent}(i)=\lfloor i/2\rfloor$, $\mathrm{left}(i)=2i$, $\mathrm{right}(i)=2i+1$. Stored level by level, left to right. Height $=\lfloor\lg n\rfloor$. The leaves are the indices $\lfloor n/2\rfloor+1,\dots,n$.
MIN-HEAPIFY$(A,i)$ — what does it assume, what does it do, and what is its running time?
Assumes the subtrees at $\mathrm{left}(i)$, $\mathrm{right}(i)$ are already min-heaps but $A[i]$ may violate the property. It picks the smallest of $A[i]$ and its children; if not $A[i]$, swaps and recurses where the big key landed — the key floats down. Time $O(h)=O(\lg n)$.
BUILD-MIN-HEAP: from which index does the loop start, why, and why is the total time $O(n)$ rather than $O(n\lg n)$?
for i = ⌊n/2⌋ downto 1: MIN-HEAPIFY(A,i) — indices above $\lfloor n/2\rfloor$ are leaves, already heaps. Cost: a node at height $h$ costs $O(h)$ and only $\lceil n/2^{h+1}\rceil$ nodes have height $h$, so $\sum_h \frac{n}{2^{h+1}}O(h)=O\big(n\sum_h h/2^h\big)=O(n)$ since $\sum h/2^h=2$.
MIN-HEAP-DECREASE-KEY$(A,i,key)$ — which direction does the element move, what is the loop condition, and the running time?
Guard: error if $key>A[i]$. Set $A[i]=key$, then float up: while i>1 and A[⌊i/2⌋]>A[i]: swap; i=⌊i/2⌋. (Opposite direction to HEAPIFY!) Time $O(\lg n)$.
List the four min-priority-queue operations and how EXTRACT-MIN works.
MINIMUM ($\Theta(1)$: return $A[1]$); EXTRACT-MIN ($O(\lg n)$: save $A[1]$, move $A[\text{heap-size}]$ to the root, shrink, MIN-HEAPIFY$(A,1)$); DECREASE-KEY ($O(\lg n)$); INSERT ($O(\lg n)$: append at the end, float up — equivalently insert $+\infty$ then decrease-key).
Heapsort: procedure, running time, in place?, stable?
BUILD-MAX-HEAP; then for $i=n$ downto $2$: swap $A[1]\leftrightarrow A[i]$, shrink the heap by one, MAX-HEAPIFY$(A,1)$. Time $\Theta(n\lg n)$, in place, not stable.
State the binary-search-tree property and how a binary tree is stored.
For every node $x$: all keys in $x$'s left subtree $\le x.key\le$ all keys in $x$'s right subtree. Storage: linked nodes with key, left, right, p (parent) + satellite data, NIL for absent children, root pointer T.root. All basic ops run in $O(h)$.
Recite the five red-black properties, in order.
1. Every node is red or black. 2. The root is black. 3. Every leaf (NIL) is black. 4. A red node has only black children. 5. All simple paths from a node down to descendant leaves have the same number of black nodes (black-height).
Height bound of a red-black tree with $n$ internal nodes — statement and two-step proof idea.
$h\le 2\lg(n+1)$. (i) Induction: the subtree at $x$ has $\ge 2^{bh(x)}-1$ internal nodes. (ii) Property 4 ⇒ at least half of any root-leaf path is black, so $bh(\text{root})\ge h/2$; hence $n\ge 2^{h/2}-1$.
RB-INSERT: the two stages, and why is the new node colored red?
Stage 1: ordinary BST insertion of $z$; color $z$ red; stage 2: RB-INSERT-FIXUP. Red because that can never violate property 5 (black-heights unchanged) — only property 4 (red parent) or 2 (root) can break, and those are fixable locally.
Insert-fixup Case 1 (uncle $y$ is red) — what happens?
Recolor only: parent and uncle become black, grandparent becomes red, and $z\gets$ grandparent — the possible violation moves two levels up and the loop may repeat. No rotation.
Insert-fixup Cases 2 and 3 (uncle black) — triangle vs. line?
Case 2 (triangle): $z$ is the inner child — rotate at the parent to straighten into a line. Case 3 (line): recolor parent black + grandparent red, rotate at the grandparent — done, loop terminates. At most 2 rotations per insertion; total $O(\lg n)$.
What does LEFT-ROTATE$(T,x)$ do, what does it preserve, and what does it cost?
$x$'s right child $y$ rises; $x$ becomes $y$'s left child; $y$'s old left subtree becomes $x$'s right subtree. Preserves the BST inorder; changes only $O(1)$ pointers — constant time. The rebalancing primitive of red-black trees.
Define the load factor and the simple uniform hashing assumption.
$\alpha=n/m$ ($n$ keys, $m$ slots) — the average chain length. Simple uniform hashing: each key is equally likely to hash into each of the $m$ slots, independently of the other keys.
Chaining: expected cost of an unsuccessful and a successful search?
Both $\Theta(1+\alpha)$ (Thms 11.1, 11.2). Unsuccessful: the searched slot's chain has expected length $\alpha$. Successful: examine the target + later-inserted colliders; the count works out to $1+\frac{\alpha}{2}-\frac{\alpha}{2n}$. With $n=O(m)$: expected $O(1)$ dictionary ops.
Name the three probing schemes of open addressing and the clustering problem of each.
Linear $h(k,i)=(h'(k)+i)\bmod m$ — primary clustering (runs grow). Quadratic $(h'(k)+c_1i+c_2i^2)\bmod m$ — secondary clustering (equal $h'$ ⇒ same path). Double hashing $(h_1(k)+i\,h_2(k))\bmod m$ — closest to uniform hashing.
Open addressing, uniform hashing, $\alpha<1$: expected probes in an unsuccessful search — bound and one-line reason?
$\le\dfrac{1}{1-\alpha}$. Each successive probe hits an occupied slot with probability $\le\alpha$, so the probe count is dominated by a geometric series $\sum_i\alpha^i$. (Insertion has the same bound — Cor. 11.7.)
Open addressing: expected probes in a successful search — bound and proof idea?
$\le\dfrac1\alpha\ln\dfrac{1}{1-\alpha}$. A search for $k$ retraces $k$'s insertion probes; the $(i{+}1)$-st inserted key cost $\le\frac{m}{m-i}$; averaging: $\frac1\alpha(H_m-H_{m-n})\le\frac1\alpha\ln\frac{1}{1-\alpha}$ by the harmonic-integral bound. At $\alpha=\frac12$: $\approx1.39$ probes.
When is a family $\mathcal H$ of hash functions universal, and why use it?
If for all $x\ne y$: $\Pr_{h\in\mathcal H}[h(x)=h(y)]\le 1/m$ (over the random choice of $h$). Defeats adversarial inputs — no fixed input is bad for a randomly drawn $h$. Example: $h_{ab}(k)=((ak+b)\bmod p)\bmod m$.
State the Master Theorem — all three cases for $T(n)=aT(n/b)+f(n)$.
Watershed $W=n^{\log_b a}$. 1. $f=O(n^{\log_b a-\varepsilon})$ ⇒ $T=\Theta(n^{\log_b a})$. 2. $f=\Theta(n^{\log_b a}\lg^k n)$, $k\ge0$ ⇒ $T=\Theta(n^{\log_b a}\lg^{k+1}n)$. 3. $f=\Omega(n^{\log_b a+\varepsilon})$ + regularity $af(n/b)\le cf(n)$, $c<1$ ⇒ $T=\Theta(f(n))$.
$f(n)=\Theta\big(n^{\log_b a}\lg^k n\big)$: answers for $k>-1$, $k=-1$, $k<-1$?
$k>-1$: $\Theta(n^{\log_b a}\lg^{k+1}n)$.  $k=-1$: $\Theta(n^{\log_b a}\lg\lg n)$ — the exam-1 case ($3T(n/3)+n/\lg n$).  $k<-1$: $\Theta(n^{\log_b a})$ (the level sum converges).
What is the regularity condition, and when must you check it?
$a\,f(n/b)\le c\,f(n)$ for some constant $c<1$ and large $n$ — the per-level costs shrink geometrically toward the leaves. Required whenever you invoke case 3. For $f=n^s\lg^t n$ with $s>\log_b a$ it holds ($a/b^s<1$), but write the line.
State the Akra–Bazzi theorem for $T(x)=g(x)+\sum_i a_iT(b_ix)$.
Solve $\;\sum_i a_ib_i^{\,p}=1\;$ for $p$; then $T(x)=\Theta\!\Big(x^p\big(1+\int_1^x g(u)\,u^{-p-1}du\big)\Big)$. One term $aT(n/b)$ gives $p=\log_b a$ — the Master watershed. Handles unequal splits like $T(n/3)+T(2n/3)+n=\Theta(n\lg n)$.
Solve $T(n)=3T(n/3)+\dfrac{n}{\lg n}$ — and which integral clinches it?
$p=1$; $\int_2^n\frac{du}{u\lg u}=\Theta(\lg\lg n)$ using $\int\frac{du}{u\ln u}=\ln\ln u$. Answer: $\Theta(n\lg\lg n)$. Vanilla Master Theorem fails — $f$ is smaller than $n$ but not polynomially.
The recursion-tree decomposition (Lemma 4.2): $T(n)=\,?$
$T(n)=\Theta\big(n^{\log_b a}\big)+\sum_{j=0}^{\log_b n-1}a^jf(n/b^j)$ — leaf cost + level costs. Level $j$: $a^j$ nodes, each $f(n/b^j)$; the three cases are exactly "level sum grows / flat / shrinks geometrically" (Lemma 4.3).
The three steps of a loop-invariant proof — name and content.
Initialization — the invariant holds before the first iteration. Maintenance — if it holds at the start of an iteration, it holds at the start of the next. Termination — the loop ends, and invariant + exit condition give the desired property. (= induction: base, step, payoff.)
Which three facts together prove a sorting algorithm correct? (Exam 1, Q1a!)
1. It terminates. 2. The output is sorted: $A'[1]\le\cdots\le A'[n]$. 3. The output is a permutation of the input — same values, same multiplicities. #3 is the classic forgotten point; for swap-only algorithms it's immediate.
Bubblesort, inner loop (for j = n downto i+1): state the invariant.
At the start of each iteration, $A[j]=\min A[j..n]$, and $A[j..n]$ is a permutation of its original contents. Termination at $j=i$ gives: $A[i]=\min A[i..n]$ — the minimum got bubbled to position $i$.
Bubblesort, outer loop: state the invariant that yields sortedness.
At the start of each iteration, $A[1..i-1]$ consists of the $i-1$ smallest original values in sorted order (and $A[i..n]$ is a permutation of the rest). At $i=n$: $A[1..n-1]$ sorted smallest values + $A[n]$ the maximum ⇒ fully sorted.
The comparison-sort lower bound — statement and three-step proof skeleton.
Any comparison sort needs $\Omega(n\lg n)$ comparisons in the worst case. (i) Model runs as a binary decision tree; (ii) correctness ⇒ all $n!$ permutations are reachable leaves, so $2^h\ge n!$; (iii) $h\ge\lg(n!)\ge\frac n2\lg\frac n2=\Omega(n\lg n)$.
Why are counting sort / radix sort not bound by $\Omega(n\lg n)$, and what do they cost?
They are not comparison sorts — they inspect key values, so the decision-tree bound doesn't apply. Counting: $\Theta(n+k)$ for keys in $\{0..k\}$, stable. Radix: $\Theta(d(n+k))$, digit-by-digit (LSD) with a stable digit sort. Bucket: expected $\Theta(n)$ on uniform input.
Quickfire: merge sort / heapsort / quicksort — worst-case time, stable?, in place?
Merge: $\Theta(n\lg n)$, stable, not in place ($\Theta(n)$ extra). Heap: $\Theta(n\lg n)$, not stable, in place. Quick: worst $\Theta(n^2)$ but expected $\Theta(n\lg n)$, not stable, in place ($O(\lg n)$ stack).
Describe counting sort in three steps. Why is its stability essential?
(1) Histogram: $C[v]=$ #keys $=v$. (2) Prefix sums: $C[v]=$ #keys $\le v$. (3) Walk the input right-to-left, placing each key at $B[C[key]]$ and decrementing. Stability (equal keys keep order) is what lets radix sort use it per digit without destroying earlier digits' work.
Randomized quicksort: $\Pr[z_i \text{ compared with } z_j]$ ($i<j$) — value and the argument.
$\dfrac{2}{j-i+1}$. Elements are compared only with a pivot. Consider the first pivot drawn from $Z_{ij}=\{z_i,\dots,z_j\}$: if strictly between, the pair separates forever; comparison happens iff it is $z_i$ or $z_j$ — 2 favourable out of $j-i+1$ equally likely.
Expected running time of randomized quicksort — result and the summation that proves it.
$O(n\lg n)$. $\mathbb E[X]=\sum_{i<j}\frac{2}{j-i+1}=\sum_{i=1}^{n-1}\sum_{k=1}^{n-i}\frac{2}{k+1}<2nH_n=O(n\lg n)$; time is $O(n+X)$ (Lemma 7.1: ≤ $n$ PARTITION calls).
RANDOMIZED-SELECT: the recurrence for the expected time, and why the answer is $\Theta(n)$.
$T(n)\le\frac2n\sum_{k=\lfloor n/2\rfloor}^{n-1}T(k)+O(n)$ — recurse into one side, worst-case the larger. Substitution with $T(k)\le ck$: $\frac{2c}{n}\cdot\frac{3n^2}{8}+an=\frac{3c}4n+an\le cn$ for $c\ge4a$. One-sided recursion ⇒ geometric total, no $\lg$ factor.
RANDOMIZE-IN-PLACE (swap $A[i]$ with $A[\mathrm{RANDOM}(i,n)]$): the probabilistic loop invariant?
Before iteration $i$: each $(i-1)$-permutation appears in $A[1..i-1]$ with probability $\frac{(n-i+1)!}{n!}$. Maintenance: $\frac{(n-i+1)!}{n!}\cdot\frac{1}{n-i+1}=\frac{(n-i)!}{n!}$. Termination $i=n+1$: every permutation with probability $1/n!$ — uniform.
Define prefix-free code, its tree representation, and the cost $B(T)$.
No codeword is a prefix of another ⇒ decoding is unambiguous. Represented by a full binary tree, characters at leaves, 0/1 = left/right, codeword length = depth. $B(T)=\sum_{c\in C}c.freq\cdot d_T(c)$ = total bits to encode the file; optimal = minimal $B(T)$.
The Huffman algorithm — procedure and running time.
Min-priority queue on frequency; repeat $n-1$ times: extract the two minima $x,y$, make a node $z$ with children $x,y$ and $z.freq=x.freq+y.freq$, insert $z$. Return the last node (root). $O(n\lg n)$ with a binary heap.
Lemma 15.2 — statement and the exchange inequality at its heart.
If $x,y$ have the lowest frequencies, some optimal tree has $x,y$ as sibling leaves at maximum depth. Exchange $x$ with a deepest leaf $a$: $B(T)-B(T')=(a.freq-x.freq)(d_T(a)-d_T(x))\ge0$ — product of two nonnegatives; likewise for $y$. Cost never increases.
Lemma 15.3 — the merge bookkeeping and the contradiction step.
Merge $x,y$ into $z$ ($z.freq=x.freq+y.freq$), $C'=(C\setminus\{x,y\})\cup\{z\}$. Key identity: $B(T)=B(T')+x.freq+y.freq$. If some $S$ beat $T$ for $C$, normalize $S$ (Lemma 15.2), contract $x,y\to z$: a tree for $C'$ cheaper than $T'$ — contradiction. So expanding an optimal $T'$ gives an optimal $T$.
Theorem 15.1 (activity selection) — statement and the exchange argument.
The earliest-finishing activity $a_m$ of subproblem $S_k$ is in some maximum-size compatible subset. Proof: take optimal $A_k$, let $a_j$ be its earliest finisher; swap $a_j\to a_m$. Since $f_m\le f_j$, everything else in $A_k$ (starting $\ge f_j\ge f_m$) stays compatible; size unchanged ⇒ still optimal.
The two ingredients every greedy proof needs — and greedy vs. DP in one sentence.
Greedy-choice property (some optimum is consistent with the locally best choice — shown by exchange) + optimal substructure. DP tries all choices and takes the best; greedy commits to one and must prove it safe.
The two hallmarks of dynamic programming, and the rod-cutting recurrence.
Optimal substructure + overlapping subproblems (cache pays). Rod cutting: $r_0=0$, $r_n=\max_{1\le i\le n}(p_i+r_{n-i})$ — $n$ subproblems × $O(n)$ choices = $O(n^2)$. Top-down = memoization; bottom-up = fill by size.
Define a B-tree of minimum degree $t$ and say why B-trees exist.
Search tree; non-root nodes hold between $t-1$ and $2t-1$ sorted keys ($k$ keys ⇒ $k+1$ children); all leaves at the same depth; height $\le\log_t\frac{n+1}2$. Built for disk storage: one node = one page read, so fat nodes (huge $t$) make the tree only 2–3 levels deep. Insert splits full nodes on the way down.
The augmentation theorem for red-black trees — hypothesis and conclusion.
If attribute $f(x)$ is computable in $O(1)$ from $x$, $x.left$, $x.right$ alone (incl. their $f$-values), then insert/delete can maintain $f$ everywhere without changing the $O(\lg n)$ cost. Why: changes propagate only up one root path; rotations are repaired locally in $O(1)$. Example: subtree sizes ⇒ order-statistic trees.
State the polynomial growth condition — with the quantifiers in the order the professor's erratum insists on.
$\forall \varphi>1\ \exists d>1\ \exists N>0\ \forall n\ge N\ \forall 1\le\psi\le\varphi:\ \frac1d f(n)\le f(\psi n)\le d\,f(n)$. The $\exists N$ comes after the $\forall\varphi$ — the lecture book has them the wrong way round. Meaning: rescaling the argument by any bounded factor changes the value by at most a constant. It is the hypothesis Akra–Bazzi needs.
Does $n^2$ satisfy the polynomial growth condition? Does $2^n$?
$n^2$ yes: given $\varphi$, take $d=\varphi^2$ — then $f(\psi n)/f(n)=\psi^2\in[1,\varphi^2]$. $2^n$ no: with $\psi=2$, $g(2n)/g(n)=2^n\to\infty$, so no constant $d$ works. Rule of thumb: any $n^a\lg^b n$ passes, genuine exponentials fail.
$T(n)=2T(\sqrt n)+\Theta(\lg n)$ — the Master Theorem doesn't apply. What do you do?
Change of variables: put $m=\lg n$ (so $n=2^m$) and $S(m)=T(2^m)$. Then $\sqrt n=2^{m/2}$, so $S(m)=2S(m/2)+\Theta(m)$ — ordinary Master case 2, giving $S(m)=\Theta(m\lg m)$. Substitute back: $T(n)=\Theta(\lg n\cdot\lg\lg n)$.
Define an AVL tree. What extra field does each node store?
A BST that is height balanced: for every node the heights of its two subtrees differ by at most 1. Each node stores $x.h$, the height of its subtree (leaf $=0$, $\mathrm{NIL}=-1$).
Prove an AVL tree with $n$ nodes has height $O(\lg n)$ — what is the recurrence, and the constant?
Let $N(h)$ be the fewest nodes at height $h$: $N(0)=1$, $N(1)=2$, $N(h)=1+N(h-1)+N(h-2)$ — the Fibonacci recurrence, with $N(h)=F_{h+3}-1$. Since $F_k=\Theta(\varphi^k)$, $n\ge F_{h+3}-1$ gives $h\le\log_\varphi(\sqrt5(n+1))-3\approx\mathbf{1.44\lg n}$. (Red-black only guarantees $2\lg(n+1)$.)
BALANCE$(x)$ in an AVL tree: what are the four cases and the rotations?
Decided by which side is heavy, then which grandchild: Left-Left ("line") → one RIGHT-ROTATE(x). Left-Right ("triangle") → LEFT-ROTATE(x.left) then RIGHT-ROTATE(x). Right-Right / Right-Left are the mirrors. At most 2 rotations, then UPDATE-HEIGHT.
AVL vs red-black: rotations per insert and per delete?
Insert: both $\le2$ rotations. Delete: AVL needs $O(\lg n)$, red-black only $\le3$ — a delete can shorten a subtree and cascade to the root. So AVL is better for lookups (tighter height), red-black for update-heavy work.
State the parenthesis theorem for DFS discovery/finish times.
For any $u,v$ exactly one holds: the intervals $[u.d,u.f]$ and $[v.d,v.f]$ are disjoint (neither is a descendant); or one is strictly contained in the other, and then the inner vertex is a descendant of the outer. Writing "(" at discovery and ")" at finish yields a well-formed parenthesis string — intervals never partially overlap.
Classify a DFS edge $(u,v)$ by timestamps: tree/forward, back, cross.
Tree or forward: $u.d<v.d<v.f<u.f$ ($v$ a descendant). Back: $v.d\le u.d<u.f\le v.f$ ($u$ a descendant of $v$). Cross: $v.d<v.f<u.d<u.f$ (disjoint; $v$ already finished). Exhaustive by the parenthesis theorem.
Two facts linking DFS edge classes to graph structure — cycles, and the undirected case?
(1) A directed graph is acyclic iff DFS finds no back edge — an $O(V+E)$ cycle test. (2) In an undirected graph only tree and back edges occur; forward and cross edges are impossible, since whichever endpoint is discovered first becomes the ancestor.
How does DFS produce a topological sort, and why is it correct?
Output vertices in decreasing finish time (push each onto a stack as it finishes), $\Theta(V+E)$. Correct because for any edge $(u,v)$ in a DAG, $v$ finishes before $u$ — otherwise $v$ would still be grey when $(u,v)$ is explored, making it a back edge and the graph cyclic.
Compute the diameter of a tree in $O(V)$ — two ways.
Double BFS: BFS from any $r$, let $a$ be farthest; BFS from $a$ — the greatest distance is the diameter. (The farthest vertex from any start is an endpoint of some longest path.) One DFS: per node, the longest path through it is $2+h(\text{tallest child})+h(\text{2nd tallest})$; take the running max. The BFS trick needs a tree — it is false on general graphs.
Longest path is NP-hard in general — why is it easy on a DAG, and what is the recurrence?
On a DAG every path is automatically simple, so DP applies. With $L(v)$ the heaviest path from $v$ to $t$: $L(t)=0$, $L(v)=\max_{(v,w)\in E}\big(w_{(v,w)}+L(w)\big)$, evaluated in reverse topological order. Each edge relaxed once: $\Theta(V+E)$.
What is an indicator random variable, and the one identity that makes it useful?
$I\{A\}=1$ if event $A$ occurs, else $0$. Then $\mathbb{E}[I\{A\}]=\Pr[A]$ — expectation of an indicator is the probability. Combined with linearity $\mathbb{E}[\sum X_i]=\sum\mathbb{E}[X_i]$ (which needs no independence), counting problems become probability problems.
State and prove Markov's inequality.
For $X\ge0$ and $t>0$: $\Pr[X\ge t]\le\mathbb{E}[X]/t$. Proof: let $I=I\{X\ge t\}$; then $tI\le X$ always (if $I=1$ then $X\ge t$; if $I=0$ then $tI=0\le X$ since $X\ge0$). Take expectations: $t\Pr[X\ge t]\le\mathbb{E}[X]$. The hypothesis $X\ge0$ is what makes the second case work.
Derive Chebyshev's inequality from Markov in one step.
Apply Markov to the nonnegative variable $(X-\mu)^2$: $\Pr[|X-\mu|\ge t]=\Pr[(X-\mu)^2\ge t^2]\le\mathbb{E}[(X-\mu)^2]/t^2=\operatorname{Var}[X]/t^2$.
Geometric distribution: give $\mathbb{E}[X]$ and $\operatorname{Var}[X]$, and the trick that gets them.
$\mathbb{E}[X]=1/p$, $\operatorname{Var}[X]=q/p^2$. Condition on the first trial: $\mathbb{E}[X]=p\cdot1+q(1+\mathbb{E}[X])$ gives the mean; squaring, $\mathbb{E}[X^2]=p+q\,\mathbb{E}[(1+X)^2]$ gives $\mathbb{E}[X^2]=(2-p)/p^2$, so $\operatorname{Var}=(2-p)/p^2-1/p^2=q/p^2$. Much cleaner than summing series.
Random search with replacement must touch every one of $n$ indices. Expected number of picks?
$nH_n=\Theta(n\lg n)$ — coupon collector. Split by phases: once $i-1$ indices are known, finding a new one is geometric with $p=(n-i+1)/n$, so the total is $\sum_{i=1}^{n}\frac{n}{n-i+1}=n\sum_j\frac1j=nH_n$.
Fastest way to prove a randomised shuffler is not uniform?
Count execution paths and check divisibility. If the procedure has $N$ equally likely paths and the output were uniform over $n!$ permutations, then $n!$ must divide $N$. PERMUTE-WITH-ALL has $N=n^n$, and $3!=6\nmid27=3^3$ — done, no case analysis. Beware: "each element is equally likely in each position" is a marginal condition and does not imply uniformity (see PERMUTE-BY-CYCLE, which has only $n$ outputs).
The two hallmarks of dynamic programming — and what happens if each is missing?
Optimal substructure and overlapping subproblems. Miss the first and DP is wrong; miss the second and DP is merely pointless — plain divide-and-conquer already suffices (merge sort has substructure but no overlap).
The four DP shapes on this course, with their subproblem and cost.
Linear — a prefix, $O(n^2)$ (rod cutting). Interval — a range $[i,j]$ split at $k$, $O(n^3)$ (matrix chain, optimal BST, palindromes, string breaking). Tree — a subtree × a small state, $O(n)$ (company party). Knapsack — items × capacity, $O(nW)$. Recognise by asking what the last decision looks like.
When does optimal substructure fail — and what is the general diagnosis?
When subproblems compete for a shared resource. Rod cutting with a limit $l_i$ on pieces of each length: the sub-solution consumes quota the outer problem also needs, so "a rod of length $n-i$" is no longer the whole subproblem — the remaining quota is part of the state. Repair = enlarge the state, at exponential cost.
The five-step exchange-argument template for proving a greedy choice safe.
(1) Let $A$ be any optimal solution, $g$ the greedy choice. (2) If $g\in A$ done; else pick the $a\in A$ that greedy beat. (3) Form $A'=(A\setminus\{a\})\cup\{g\}$ and show it is still feasible and no worse. (4) So some optimal solution contains $g$. (5) Induct on the rest. Activity selection, Huffman and fractional knapsack are all this.
Fractional vs 0–1 knapsack: which is greedy, which is DP, and why is $O(nW)$ not polynomial?
Fractional — greedy by density $v_i/w_i$, $O(n)$ with weighted-median selection. 0–1 — DP, $K[i,w]=\max(K[i-1,w],\,v_i+K[i-1,w-w_i])$, $O(nW)$. The input encodes $W$ in $\Theta(\lg W)$ bits, so $O(nW)$ is exponential in the input length — pseudo-polynomial. That is why 0–1 is NP-hard and fractional is linear.
Name two places on sheet 10 where a plausible greedy rule fails.
(1) Activity selection by shortest duration: $(0,10),(9,11),(10,20)$ — greedy takes $(9,11)$ and blocks both others, 1 instead of 2. Also fails for earliest-start and fewest-conflicts. (2) Weighted activity selection: greedy fails once activities carry values; use DP with $\mathrm{OPT}(j)=\max(v_j+\mathrm{OPT}(\mathrm{prev}(j)),\mathrm{OPT}(j-1))$, $O(n\lg n)$.
