1 · Correctness of bubblesort 8 pts

Bubblesort works by repeatedly swapping adjacent elements that are out of order. The procedure is

1: procedure BUBBLESORT(A, n)
2:   for i = 1 to n−1 do
3:     for j = n downto i+1 do
4:       if A[j] < A[j−1] then
5:         exchange A[j] with A[j−1]
6:       end if
7:     end for
8:   end for
9: end procedure
  1. Let $A'$ denote the array $A$ after BUBBLESORT$(A,n)$ is executed. To prove that BUBBLESORT is correct, you need to prove that it terminates and that $A'[1]\le A'[2]\le\cdots\le A'[n]$. In order to show that BUBBLESORT actually sorts, what else do you need to prove? 1
  2. State a precise loop invariant for the for $j=n$ downto $i+1$ loop in lines 3–7 and prove that it holds. 3
  3. Using the termination condition of the loop invariant stated and proved above, state a loop invariant for the for $i=1$ to $n-1$ loop in lines 2–8 that allows you to prove the inequality above for the $A'$ array. 2
  4. Prove that the loop invariant above holds and conclude that BUBBLESORT works. 2
Model solution — Q1 (this is CLRS Problem 2-2, verbatim)

(a) We must also prove that $A'$ is a permutation of the original array $A$ — it contains exactly the same values with the same multiplicities. Sortedness alone is not enough: a procedure that overwrites $A$ with $[1,2,\dots,n]$ satisfies $A'[1]\le\cdots\le A'[n]$ but doesn't sort $A$. For BUBBLESORT this is immediate, because the only write it ever performs is an exchange of two entries (line 5), and exchanges preserve the multiset of values.

(b) Fix an iteration of the outer loop, i.e. a value of $i$.

Inner invariant. At the start of each iteration of the loop of lines 3–7, $\;A[j]=\min\{A[k] : j\le k\le n\}$, and the subarray $A[j..n]$ is a permutation of the values that were in $A[j..n]$ when the loop started.

Initialization — Before the first iteration, $j=n$. The subarray $A[n..n]$ contains a single element, so trivially $A[n]=\min A[n..n]$, and nothing has been moved yet.

Maintenance — Suppose the invariant holds at the start of an iteration: $A[j]=\min A[j..n]$. The body compares $A[j]$ with $A[j-1]$ and swaps them if $A[j]<A[j-1]$. Afterwards $A[j-1]=\min\{A[j-1],\,\text{old }A[j]\}=\min\{A[j-1],\,\min A[j..n]\}=\min A[j-1..n]$. Only positions $j-1,j$ were touched, so $A[j-1..n]$ is still a permutation of its original values. Decrementing $j$ makes the invariant hold at the start of the next iteration.

Termination — The loop ends when $j=i$. The invariant then says: $A[i]=\min A[i..n]$ — the inner loop has "bubbled" the smallest element of $A[i..n]$ into position $i$, permuting $A[i..n]$ and touching nothing left of $i$.

(c)

Outer invariant. At the start of each iteration of the loop of lines 2–8, the subarray $A[1..i-1]$ consists of the $i-1$ smallest values of the original array, in sorted order; and $A[i..n]$ is a permutation of the remaining $n-i+1$ original values. In particular every element of $A[1..i-1]$ is $\le$ every element of $A[i..n]$.

(d)

Initialization — $i=1$: the subarray $A[1..0]$ is empty, so the claim is vacuously true, and $A[1..n]$ is the whole original array.

Maintenance — Assume the invariant at the start of the iteration for $i$. By the termination of the inner invariant (part b), after lines 3–7 run we have $A[i]=\min A[i..n]$, with $A[i..n]$ merely permuted and $A[1..i-1]$ untouched. Then: (i) $A[1..i-1]$ is still the sorted list of the $i-1$ smallest values; (ii) $A[i]$ is the minimum of the remaining values, hence the $i$-th smallest overall, and $A[i-1]\le A[i]$ since everything in $A[1..i-1]$ is $\le$ everything in $A[i..n]$. So $A[1..i]$ is the sorted list of the $i$ smallest values and $A[i+1..n]$ holds the rest — exactly the invariant for $i+1$.

Termination — The outer loop ends with $i=n$. The invariant gives: $A[1..n-1]$ contains the $n-1$ smallest original values in sorted order, and $A[n]$ holds the remaining (largest) value, so $A'[1]\le A'[2]\le\cdots\le A'[n]$. Termination itself is clear: both loops are finite for-loops (the inner runs $n-i$ times, the outer $n-1$ times, $\Theta(n^2)$ iterations total). Together with the permutation property from (a), BUBBLESORT sorts correctly. $\blacksquare$

Grader notes — where the points live (a) the word permutation is the point — a classic 1-pt trap. (b) 1 pt for a precise invariant (quantify the exact indices; "the array gets more sorted" earns 0), 2 pts for the three labelled steps. (c) the invariant must be strong enough — it needs both "sorted" and "$\le$ everything to the right" (or "the $i-1$ smallest"), otherwise maintenance fails. (d) explicitly use the inner loop's termination in the maintenance step, and don't forget to say why the loops terminate.

2 · Runtime analysis 8 pts

For the following recursions, give asymptotically tight upper and lower bounds for $T(n)$.

  1. $T(n)=16\,T(n/4)+n^2$ 2
  2. $T(n)=3\,T(n/3)+\dfrac{n}{\lg n}$ 2
  3. $T(n)=4\,T(n/2)+n^2\lg n$ 2
  4. $T(n)=2\,T(n/4)+\sqrt{n}$ 2
Model solution — Q2 (note: all four are the case-2 / log-factor family!)

"Tight upper and lower bounds" = give $\Theta(\cdot)$, justified. In each part compute the watershed $n^{\log_b a}$ and compare with $f(n)$.

(a) $a=16$, $b=4$: $n^{\log_4 16}=n^2$. Here $f(n)=n^2=\Theta(n^2\lg^0 n)$ — exact match (case 2 of the Master Theorem, $k=0$). Hence $$T(n)=\Theta(n^2\lg n).$$

(b) $a=3$, $b=3$: $n^{\log_3 3}=n$, and $f(n)=n/\lg n=\Theta(n\lg^{-1}n)$. The basic Master Theorem does not apply: $f$ is smaller than $n$ but only by a $\lg$ factor, so it is not polynomially smaller (case 1 fails), and it isn't $\Theta(n)$ either (case 2 fails). Two clean routes:

  • Extended case 2 with $k=-1$: if $f(n)=\Theta(n^{\log_b a}\lg^{-1}n)$ then $T(n)=\Theta(n^{\log_b a}\lg\lg n)$.
  • Akra–Bazzi: $p$ solves $3\cdot(1/3)^p=1\Rightarrow p=1$. Then $$T(n)=\Theta\!\Big(n^p\Big(1+\int_2^n\frac{f(u)}{u^{p+1}}\,du\Big)\Big) =\Theta\!\Big(n\Big(1+\int_2^n\frac{du}{u\lg u}\Big)\Big),$$ and $\int_2^n\frac{du}{u\lg u}=\ln 2\,\big[\ln\ln u\big]_2^n=\Theta(\lg\lg n)$.

Either way, $$T(n)=\Theta(n\lg\lg n).$$

(c) $a=4$, $b=2$: $n^{\log_2 4}=n^2$, and $f(n)=n^2\lg n=\Theta(n^2\lg^1 n)$ — extended case 2 with $k=1$: $$T(n)=\Theta(n^2\lg^2 n).$$

(d) $a=2$, $b=4$: $n^{\log_4 2}=n^{1/2}=\sqrt n$, and $f(n)=\sqrt n$ — exact match again (case 2, $k=0$): $$T(n)=\Theta(\sqrt n\,\lg n).$$

Grader notes Show the three ingredients every time: $a,b$ and the watershed $n^{\log_b a}$ (computed, not asserted); the comparison with $f(n)$; the case invoked, then the $\Theta$ answer. Part (b) is the differentiator — it's there precisely to catch people who only know the three vanilla cases. Know the $k=-1\Rightarrow\lg\lg n$ rule and be able to run Akra–Bazzi. Full method + ~20 drills: recurrence drill bank.

3 · Heaps 8 pts

Describe what a heap is and what it is usually used for. Especially, talk about the following points:

  1. Explain how a heap is represented in an array. 1
  2. Describe the algorithms MIN-HEAPIFY and BUILD-MIN-HEAP for constructing a min heap. 3
  3. Explain which algorithms are needed to turn a min heap into a min priority queue, and describe the algorithm MIN-HEAP-DECREASE-KEY. 3
  4. What are the running times of MIN-HEAPIFY and MIN-HEAP-DECREASE-KEY? 1
Model solution — Q3

A (binary) min-heap is a nearly complete binary tree — every level full except possibly the last, which is filled left to right — satisfying the min-heap property: for every node $i$ other than the root, $A[\mathrm{parent}(i)]\le A[i]$. The minimum therefore sits at the root. Heaps are used for heapsort and, above all, as priority queues.

(a) Array representation. Store the tree level by level, left to right, in $A[1..n]$: the root is $A[1]$, and for a node at index $i$, $\mathrm{parent}(i)=\lfloor i/2\rfloor$, $\mathrm{left}(i)=2i$, $\mathrm{right}(i)=2i+1$. No pointers needed; A.heap-size tracks how much of the array is heap.

(b) MIN-HEAPIFY fixes a single violation: it assumes the subtrees rooted at $\mathrm{left}(i)$ and $\mathrm{right}(i)$ are already min-heaps, but $A[i]$ may be larger than its children. It lets $A[i]$ float down:

MIN-HEAPIFY(A, i)
  l = 2i;  r = 2i+1;  smallest = i
  if l ≤ A.heap-size and A[l] < A[smallest]: smallest = l
  if r ≤ A.heap-size and A[r] < A[smallest]: smallest = r
  if smallest ≠ i:
    exchange A[i] with A[smallest]
    MIN-HEAPIFY(A, smallest)          // recurse where the big key landed

BUILD-MIN-HEAP turns an arbitrary array into a heap. The elements $A[\lfloor n/2\rfloor{+}1..n]$ are leaves — already 1-element heaps — so it suffices to heapify the internal nodes bottom-up:

BUILD-MIN-HEAP(A, n)
  A.heap-size = n
  for i = ⌊n/2⌋ downto 1:
    MIN-HEAPIFY(A, i)

(Correctness by the invariant: at the start of each iteration, nodes $i+1,\dots,n$ are roots of min-heaps. Runtime is $O(n)$ — not $O(n\lg n)$ — because most nodes sit at small heights: $\sum_{h}\lceil n/2^{h+1}\rceil\,O(h)=O(n)$.)

(c) Min-priority queue. A priority queue maintains a dynamic set with operations: MIN-HEAP-MINIMUM (return $A[1]$), MIN-HEAP-EXTRACT-MIN (remove and return the min: save $A[1]$, move $A[\text{heap-size}]$ to the root, shrink, MIN-HEAPIFY$(A,1)$), MIN-HEAP-DECREASE-KEY, and MIN-HEAP-INSERT (append the new key at the end, then float it up — implementable as insert $+\infty$ then decrease-key).

MIN-HEAP-DECREASE-KEY$(A,i,key)$ lowers the key at position $i$ and restores the heap property by floating the element up (the mirror image of heapify's float-down):

MIN-HEAP-DECREASE-KEY(A, i, key)
  if key > A[i]: error "new key is larger than current key"
  A[i] = key
  while i > 1 and A[⌊i/2⌋] > A[i]:
    exchange A[i] with A[⌊i/2⌋]
    i = ⌊i/2⌋

(d) Running times. Both MIN-HEAPIFY and MIN-HEAP-DECREASE-KEY walk one root-to-leaf (resp. leaf-to-root) path of a tree of height $\lfloor\lg n\rfloor$, doing $O(1)$ work per level: both are $O(\lg n)$.

Grader notes The pseudocode is the deliverable — write MIN-HEAPIFY, BUILD-MIN-HEAP and DECREASE-KEY from memory until it's automatic. Say the index formulas ($\lfloor i/2\rfloor,2i,2i{+}1$), the heap property, and mention that BUILD-MIN-HEAP starts at $\lfloor n/2\rfloor$ because the rest are leaves. Bonus credibility: BUILD-MIN-HEAP is $O(n)$.

4 · Red-black trees 6 pts

  1. Define what a binary search tree is, and describe how binary trees are stored. 1
  2. What are the properties that define a red-black tree? 1
  3. Provide the algorithms for inserting a new element in a red-black tree. 4
Model solution — Q4

(a) A binary search tree is a binary tree whose nodes each store a key, satisfying the BST property: for every node $x$, every key in $x$'s left subtree is $\le x.key$, and every key in $x$'s right subtree is $\ge x.key$. A binary tree is stored as linked nodes: each node holds key (+ satellite data) and three pointers — left, right, p (parent); absent children are NIL, and the tree is accessed through a root pointer. (Red-black trees use a single black sentinel T.nil for all NILs.)

(b) A red-black tree is a BST with one extra bit per node (its color) satisfying the five red-black properties:

  1. Every node is either red or black.
  2. The root is black.
  3. Every leaf (NIL) is black.
  4. A red node has only black children (never two reds in a row on a path).
  5. For every node, all simple paths from it down to descendant leaves contain the same number of black nodes (its black-height).

These force height $\le 2\lg(n+1)$, so all dictionary operations run in $O(\lg n)$.

(c) Insertion has two stages. Stage 1: ordinary BST insertion of $z$, then color $z$ red (red, so property 5 is never broken — only possibly property 4, or 2 if $z$ is the root). Stage 2: repair with rotations + recoloring.

RB-INSERT(T, z)
  x = T.root;  y = T.nil
  while x ≠ T.nil:                 // walk down to the insertion point
    y = x
    if z.key < x.key: x = x.left else: x = x.right
  z.p = y
  if y == T.nil: T.root = z
  else if z.key < y.key: y.left = z
  else: y.right = z
  z.left = T.nil;  z.right = T.nil;  z.color = RED
  RB-INSERT-FIXUP(T, z)

The fixup loop runs while $z$'s parent is red (a property-4 violation). Let $z.p.p$ be the grandparent and $y$ the uncle (the grandparent's other child). Three cases (shown for $z.p$ a left child; mirror otherwise):

RB-INSERT-FIXUP(T, z)
  while z.p.color == RED:
    if z.p == z.p.p.left:
      y = z.p.p.right                        // uncle
      if y.color == RED:                     // Case 1: red uncle → recolor
        z.p.color = BLACK;  y.color = BLACK
        z.p.p.color = RED;  z = z.p.p        // push the problem two levels up
      else:
        if z == z.p.right:                   // Case 2: black uncle, “triangle”
          z = z.p;  LEFT-ROTATE(T, z)        // convert to Case 3
        z.p.color = BLACK                    // Case 3: black uncle, “line”
        z.p.p.color = RED
        RIGHT-ROTATE(T, z.p.p)               // terminates the loop
    else: (same, with “left” and “right” exchanged)
  T.root.color = BLACK                       // restore property 2

The rotation primitive (constant time, preserves the BST property):

LEFT-ROTATE(T, x)          // x’s right child y rises; x becomes y’s left child
  y = x.right
  x.right = y.left
  if y.left ≠ T.nil: y.left.p = x
  y.p = x.p
  if x.p == T.nil: T.root = y
  else if x == x.p.left: x.p.left = y
  else: x.p.right = y
  y.left = x;  x.p = y

In words: Case 1 (red uncle): recolor parent + uncle black, grandparent red, move $z$ up two levels — may repeat. Case 2 (black uncle, $z$ the "inner" child): a rotation at the parent turns it into Case 3. Case 3 (black uncle, $z$ the "outer" child): recolor parent black / grandparent red and rotate at the grandparent — done. Total: $O(\lg n)$ time, at most 2 rotations per insertion.

Grader notes 4 points = they want the real algorithms, not a story. Structure your answer as: BST insert → color red → why only property 4 can break → the three fixup cases by uncle color and triangle/line shape, each with its recolor/rotation. Drawing the three cases as little diagrams earns clarity points. Diagrams + more detail: data-structure notes → red-black trees.

5 · Huffman codes 10 pts

  1. Provide the algorithm for constructing a Huffman code. 2
  2. Prove that the Huffman code algorithm produces an optimal prefix-free code. 8
Model solution — Q5 (= CLRS Lemmas 15.2, 15.3 + Theorem 15.4)

Setup. A prefix-free code assigns each character a binary codeword such that no codeword is a prefix of another; equivalently, the code is a full binary tree $T$ (every internal node has two children) with the characters at the leaves, 0 = "go left", 1 = "go right". The codeword length of $c$ is its depth $d_T(c)$, and the cost of the tree is $$B(T)=\sum_{c\in C} c.freq\cdot d_T(c),$$ the number of bits needed to encode the file. A code/tree is optimal if it minimizes $B(T)$.

(a) The algorithm. Greedily merge the two least-frequent nodes, using a min-priority queue $Q$ keyed on frequency:

HUFFMAN(C)
  n = |C|
  Q = C                              // build min-priority queue of the characters
  for i = 1 to n−1:
    z = new node
    z.left  = x = EXTRACT-MIN(Q)
    z.right = y = EXTRACT-MIN(Q)
    z.freq  = x.freq + y.freq
    INSERT(Q, z)
  return EXTRACT-MIN(Q)              // root of the code tree

With a binary min-heap: $n-1$ iterations × $O(\lg n)$ per queue operation = $O(n\lg n)$.

(b) Optimality. Two lemmas, then induction.

Lemma 1 (greedy choice — CLRS 15.2). Let $x,y$ be two characters of lowest frequency in $C$. Then there exists an optimal prefix-free code for $C$ in which the codewords of $x$ and $y$ have the same length and differ only in the last bit — i.e. some optimal tree has $x$ and $y$ as sibling leaves at maximum depth.

Proof. Take any optimal tree $T$. Since $T$ is full, it has two sibling leaves $a,b$ at maximum depth; label them so that $a.freq\le b.freq$, and label $x,y$ so that $x.freq\le y.freq$. Because $x,y$ have the two smallest frequencies of all, $x.freq\le a.freq$ and $y.freq\le b.freq$. (If $x=b$ or $y=a$, swap roles/names — the boundary cases are routine; if $\{x,y\}=\{a,b\}$ we are already done.) Let $T'$ be $T$ with $x$ and $a$ exchanged. Then $$B(T)-B(T')=(a.freq-x.freq)\,\bigl(d_T(a)-d_T(x)\bigr)\;\ge\;0,$$ since both factors are $\ge 0$ ($a$ sits at maximum depth). Exchanging $y$ and $b$ in $T'$ to get $T''$ likewise gives $B(T')-B(T'')\ge 0$. So $B(T'')\le B(T)$; as $T$ was optimal, $T''$ is optimal too — and it has $x,y$ as maximum-depth siblings. $\square$

Lemma 2 (optimal substructure — CLRS 15.3). Let $x,y$ be two minimum-frequency characters of $C$. Define $C'=(C\setminus\{x,y\})\cup\{z\}$ where $z$ is a new character with $z.freq=x.freq+y.freq$. If $T'$ is a tree of an optimal prefix-free code for $C'$, then the tree $T$ obtained from $T'$ by replacing the leaf $z$ with an internal node having children $x$ and $y$ is an optimal prefix-free code tree for $C$.

Proof. First relate the costs. Each $c\in C\setminus\{x,y\}$ has $d_T(c)=d_{T'}(c)$, while $d_T(x)=d_T(y)=d_{T'}(z)+1$, so $$B(T)=B(T')+x.freq+y.freq .$$ Suppose, for contradiction, $T$ is not optimal for $C$: some tree $S$ has $B(S)<B(T)$. By Lemma 1 we may assume $S$ has $x,y$ as sibling leaves. Replace $x$, $y$ and their common parent in $S$ by a single leaf $z$ (with $z.freq = x.freq+y.freq$) to obtain a tree $S'$ for $C'$ with $$B(S')=B(S)-x.freq-y.freq\;<\;B(T)-x.freq-y.freq\;=\;B(T'),$$ contradicting the optimality of $T'$ for $C'$. $\square$

Theorem (CLRS 15.4). Procedure HUFFMAN produces an optimal prefix-free code.

Proof. Induction on $n=|C|$. Base: $n=2$ — any prefix-free code needs at least one bit per character, and HUFFMAN outputs codewords $0$ and $1$, which is optimal. Step: let $n>2$ and assume HUFFMAN is optimal for alphabets of size $n-1$. On input $C$, the first iteration extracts two minimum-frequency characters $x,y$ and replaces them by a merged node $z$ with $z.freq=x.freq+y.freq$; the remaining $n-2$ iterations run HUFFMAN on exactly the alphabet $C'$ of Lemma 2. By the induction hypothesis, the resulting tree $T'$ is optimal for $C'$; the final output $T$ is $T'$ with the leaf $z$ expanded into the siblings $x,y$. By Lemma 2, $T$ is optimal for $C$. (Lemma 1 is what makes the greedy first step safe: an optimal solution with $x,y$ as bottom-level siblings exists, so restricting attention to such solutions loses nothing.) $\blacksquare$

Grader notes — 8 points, budget them Roughly: setup (tree ↔ prefix-free code, cost $B(T)$) ≈ 1; Lemma 1 statement + exchange argument with the product-of-two-nonnegatives inequality ≈ 3; Lemma 2 statement + the $B(T)=B(T')+x.freq+y.freq$ computation + contradiction ≈ 3; assembling the induction ≈ 1. The two displayed equations are the heart — memorize them. This was the single biggest item on the paper; it is flagged (Thm 15.4 + Lemmas 15.2/15.3) and it appeared. Assume it can appear again.
