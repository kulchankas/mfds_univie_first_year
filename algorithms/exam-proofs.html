① Loop invariants — the universal template EXAM 1

Main idea A loop invariant is an induction proof wearing work clothes: Initialization = base case, Maintenance = induction step, Termination = "now cash it in".

To prove a loop correct, state a property $P(\text{loop variable})$ of the program state and show:

  1. Initialization — $P$ holds just before the first iteration.
  2. Maintenance — if $P$ holds at the start of an iteration, it holds at the start of the next one.
  3. Termination — the loop terminates and, combined with the exit condition, $P$ yields the property you actually wanted.

For a sorting algorithm, full correctness always needs three facts: the algorithm terminates; the output is sorted; the output is a permutation of the input. Forgetting the permutation clause is the classic dropped point — it was literally question 1(a) on exam 1.

The bubblesort version (exam 1, question 1) is fully worked on the mock-exam page. Here is the other canonical exemplar, the most likely rotation:

Worked: correctness of INSERTION-SORT

INSERTION-SORT(A, n)
  for i = 2 to n:
    key = A[i]
    j = i − 1
    while j > 0 and A[j] > key:
      A[j+1] = A[j]                // shift right
      j = j − 1
    A[j+1] = key
Outer invariant At the start of each iteration of the for loop, the subarray $A[1..i-1]$ consists of the elements originally in $A[1..i-1]$, in sorted order.

Initialization — $i=2$: $A[1..1]$ is a single element, trivially sorted, and untouched so far.

Maintenance — Fix an iteration; the while loop shifts $A[j]$ one place right as long as $A[j]>key$. Its own invariant: at the start of each test, $A[j{+}2..i]$ holds, shifted one place right, the values formerly in $A[j{+}1..i-1]$, and every one of them is $>key$; $A[1..j]$ is unchanged. (Initialization: $j=i-1$, the range $A[i{+}1..i]$ is empty. Maintenance: one shift extends it. Termination: the loop stops when $j=0$ or $A[j]\le key$.) Writing $key$ into $A[j{+}1]$ then places it directly after the last element $\le key$ and directly before the shifted block of elements $>key$ — so $A[1..i]$ is the old $A[1..i]$, sorted, and the outer invariant holds for $i+1$.

Termination — The for loop ends with $i=n+1$; the invariant says $A[1..n]$ contains the original elements in sorted order. Both loops are bounded ($i$ increases, $j$ strictly decreases), so the algorithm terminates. Only shifts of existing values + reinsertion of the saved $key$ occur, so the multiset of values is preserved. $\blacksquare$

Exam tip Always quantify indices exactly ("$A[1..i-1]$ consists of…"), never "the array is partially sorted". State the inner invariant separately when the exam asks for it — the outer maintenance step should invoke the inner loop's termination, exactly as in exam 1 Q1(c).

② The Master Theorem and its proof machinery EXAM 1

Main idea Unroll $T(n)=aT(n/b)+f(n)$ into a recursion tree: level $j$ costs $a^j f(n/b^j)$ and the leaves cost $\Theta(n^{\log_b a})$. Whether the level costs grow, stay flat, or shrink geometrically toward the leaves gives the three cases.
Theorem 4.1 — Master Theorem Let $a\ge 1$, $b>1$, $f(n)\ge 0$, and $T(n)=a\,T(n/b)+f(n)$ (with $n/b$ meaning $\lfloor n/b\rfloor$ or $\lceil n/b\rceil$). Compare $f$ with the watershed $n^{\log_b a}$:
  1. If $f(n)=O(n^{\log_b a-\varepsilon})$ for some $\varepsilon>0$, then $T(n)=\Theta(n^{\log_b a})$.
  2. If $f(n)=\Theta(n^{\log_b a}\lg^k n)$ with $k\ge 0$, then $T(n)=\Theta(n^{\log_b a}\lg^{k+1} n)$.
  3. If $f(n)=\Omega(n^{\log_b a+\varepsilon})$ for some $\varepsilon>0$, and $f$ satisfies the regularity condition $a f(n/b)\le c f(n)$ for some constant $c<1$ and large $n$, then $T(n)=\Theta(f(n))$.
Lemma 4.2 — recursion-tree decomposition For $n$ an exact power of $b$, $$T(n)=\Theta\big(n^{\log_b a}\big)+\sum_{j=0}^{\log_b n-1}a^j\,f\!\big(n/b^j\big).$$

Proof. Unroll the recurrence into its recursion tree. The root costs $f(n)$ and has $a$ children, each a subproblem of size $n/b$; at depth $j$ there are $a^j$ nodes, each costing $f(n/b^j)$, so level $j$ contributes $a^j f(n/b^j)$. The tree has depth $\log_b n$ (subproblem size reaches 1). The bottom level consists of $a^{\log_b n}=n^{\log_b a}$ leaves, each solved in constant time — total $\Theta(n^{\log_b a})$. Summing leaf cost plus the internal levels $j=0,\dots,\log_b n-1$ gives the claim. $\blacksquare$

Lemma 4.3 — evaluating the level sum Let $g(n)=\displaystyle\sum_{j=0}^{\log_b n-1}a^j f(n/b^j)$. Then: (1) if $f(n)=O(n^{\log_b a-\varepsilon})$ then $g(n)=O(n^{\log_b a})$; (2) if $f(n)=\Theta(n^{\log_b a})$ then $g(n)=\Theta(n^{\log_b a}\lg n)$; (3) if $f$ satisfies the regularity condition then $g(n)=\Theta(f(n))$.

Proof.

  • (1) Costs grow toward the leaves. Substituting the bound on $f$: $a^j f(n/b^j)=O\!\big(a^j (n/b^j)^{\log_b a-\varepsilon}\big)=O\!\big(n^{\log_b a-\varepsilon}\,(b^{\varepsilon})^{j}\big)$, using $a^j/(b^{\log_b a})^j=1$. The sum is geometric with ratio $b^\varepsilon>1$, hence dominated by its last term $j=\log_b n-1$: $g(n)=O\!\big(n^{\log_b a-\varepsilon}\cdot b^{\varepsilon\log_b n}\big)=O\!\big(n^{\log_b a-\varepsilon}\cdot n^{\varepsilon}\big)=O(n^{\log_b a})$.
  • (2) Every level costs the same. $a^j f(n/b^j)=\Theta\!\big(a^j (n/b^j)^{\log_b a}\big)=\Theta(n^{\log_b a})$ — the $a^j$ cancels exactly. There are $\log_b n=\Theta(\lg n)$ levels, so $g(n)=\Theta(n^{\log_b a}\lg n)$.
  • (3) Costs shrink toward the leaves. Iterating the regularity condition, $a^j f(n/b^j)\le c^j f(n)$. Hence $g(n)\le f(n)\sum_{j\ge 0}c^j=\frac{1}{1-c}f(n)=O(f(n))$; and trivially $g(n)\ge f(n)$ (the $j=0$ term). So $g(n)=\Theta(f(n))$.
Theorem 4.4 — assembling the Master Theorem (powers of $b$) For $n$ an exact power of $b$, the three cases of Theorem 4.1 hold.

Proof. By Lemma 4.2, $T(n)=\Theta(n^{\log_b a})+g(n)$. Insert Lemma 4.3: case 1: $g=O(n^{\log_b a})$, so the leaves dominate and $T=\Theta(n^{\log_b a})$. Case 2 ($k=0$): $g=\Theta(n^{\log_b a}\lg n)$ dominates the leaf term, $T=\Theta(n^{\log_b a}\lg n)$; the general $k\ge 0$ variant follows the same computation with $f(n/b^j)=\Theta\big((n/b^j)^{\log_b a}\lg^k(n/b^j)\big)$, whose level costs still sum to $\Theta(n^{\log_b a}\lg^{k+1}n)$. Case 3: $g=\Theta(f(n))$ and $f(n)=\Omega(n^{\log_b a+\varepsilon})$ dominates the leaves, so $T=\Theta(f(n))$. Extending from exact powers of $b$ to all $n$ (floors/ceilings) is a technical sandwich argument and doesn't change the answers. $\blacksquare$

Exam tip The examinable skeleton is: recursion tree → level cost $a^jf(n/b^j)$ → leaves $n^{\log_b a}$ → geometric growth / flat / geometric decay. If asked to prove the Master Theorem, that's Lemma 4.2 + Lemma 4.3 + two lines of assembly. For applying it fast (incl. the extended case 2 with $k=-1\Rightarrow\lg\lg n$), drill with the recurrence bank.

③ The Akra–Bazzi theorem EXAM 1

Main idea The Master Theorem generalized: unequal subproblem sizes are fine. Find the exponent $p$ that balances the recursion ($\sum a_ib_i^p=1$), then a single integral measures how much the driving function adds on top of $x^p$.
Theorem (Akra–Bazzi) Consider $T(x)=g(x)+\displaystyle\sum_{i=1}^{k}a_i\,T(b_i x)$ for $x\ge x_0$, where each $a_i>0$, each $b_i\in(0,1)$, and $g$ is nonnegative with polynomial growth (small perturbations $T(b_ix+h_i(x))$ with $|h_i(x)|=O(x/\lg^2 x)$ are allowed). Let $p$ be the unique real solving $$\sum_{i=1}^{k}a_i\,b_i^{\,p}=1.$$ Then $$T(x)=\Theta\!\left(x^{p}\left(1+\int_{1}^{x}\frac{g(u)}{u^{\,p+1}}\,du\right)\right).$$

Recipe. (i) Solve $\sum a_ib_i^p=1$ for $p$ — with a single term $aT(n/b)$ this gives $p=\log_b a$, recovering the Master watershed. (ii) Compute $\int^x g(u)/u^{p+1}\,du$. (iii) Multiply by $x^p$. (If $g$ vanishes or misbehaves near the lower limit — e.g. $g(u)=u/\lg u$ at $u=1$ — start the integral at 2; it changes the value only by a constant.)

Worked examples.

  • $T(n)=T(n/3)+T(2n/3)+n$: solve $(1/3)^p+(2/3)^p=1\Rightarrow p=1$. Integral $\int_1^n u/u^2\,du=\ln n$. So $T(n)=\Theta(n\lg n)$.
  • $T(n)=3T(n/3)+n/\lg n$ (exam 1!): $p=1$; $\int_2^n \frac{u/\lg u}{u^2}du=\int_2^n\frac{du}{u\lg u}=\Theta(\lg\lg n)$. So $T(n)=\Theta(n\lg\lg n)$.
  • $T(n)=T(n/5)+T(7n/10)+n$ (the SELECT recurrence): $(1/5)^p+(7/10)^p=1$ has its solution at some $p<1$ (at $p=1$ the left side is $0.2+0.7=0.9<1$). Then $\int_1^n u^{-p}\,du=\Theta(n^{1-p})$ and $T(n)=\Theta(n^p\cdot n^{1-p})=\Theta(n)$ — linear-time selection.
Exam tip On exam 1 Akra–Bazzi was the intended tool for $T(n)=3T(n/3)+n/\lg n$. Know the statement by heart (the balance equation and the integral), and remember the two standard integrals: $\int\!\frac{du}{u}=\ln u$ and $\int\!\frac{du}{u\ln u}=\ln\ln u$.

④ Lemma 5.4 — RANDOMIZE-IN-PLACE computes a uniform random permutation

Main idea A loop-invariant proof about probabilities: just before iteration $i$, every possible $(i-1)$-permutation sits in $A[1..i-1]$ with exactly the probability it should — $(n-i+1)!/n!$.
RANDOMIZE-IN-PLACE(A, n)
  for i = 1 to n:
    swap A[i] with A[RANDOM(i, n)]   // RANDOM(i,n): uniform on {i,…,n}
Lemma 5.4 RANDOMIZE-IN-PLACE computes a uniform random permutation: each of the $n!$ permutations is produced with probability $1/n!$.

Proof. Call an ordered choice of $k$ distinct elements out of the $n$ a $k$-permutation; there are $n!/(n-k)!$ of them.

Invariant Just before the $i$-th iteration, for each $(i-1)$-permutation $\langle x_1,\dots,x_{i-1}\rangle$, the probability that $A[1..i-1]$ contains exactly it, in this order, is $\dfrac{(n-i+1)!}{n!}$.

Initialization — $i=1$: $A[1..0]$ holds the empty $0$-permutation with probability $\frac{(n-0)!}{n!}=1$. True.

Maintenance — Fix an $i$-permutation $\langle x_1,\dots,x_i\rangle$. The event "$A[1..i]$ holds it after iteration $i$" is the intersection of $E_1$ = "$A[1..i-1]$ held $\langle x_1,\dots,x_{i-1}\rangle$ before" and $E_2$ = "iteration $i$ swaps $x_i$ into position $i$". By the invariant, $\Pr[E_1]=\frac{(n-i+1)!}{n!}$. Given $E_1$, the element $x_i$ sits somewhere in $A[i..n]$, and $\mathrm{RANDOM}(i,n)$ picks its position with probability $\frac{1}{n-i+1}$. Hence $$\Pr[E_1\cap E_2]=\frac{(n-i+1)!}{n!}\cdot\frac{1}{n-i+1}=\frac{(n-i)!}{n!},$$ which is exactly the invariant for $i+1$.

Termination — The loop ends with $i=n+1$: each $n$-permutation appears in $A[1..n]$ with probability $\frac{(n-n)!}{n!}=\frac{1}{n!}$ — a uniform random permutation. $\blacksquare$

Exam tip This proof doubles as the professor's two favourite themes in one — a loop invariant and probability. Practice writing the conditional-probability product line cleanly.

⑤ Theorem 7.4 — expected running time of randomized quicksort

Main idea Count comparisons, not time. $z_i$ and $z_j$ (the $i$-th and $j$-th smallest) are compared iff the first pivot drawn from $\{z_i,\dots,z_j\}$ is one of the two endpoints — probability $\frac{2}{j-i+1}$. Summing gives a harmonic series → $O(n\lg n)$.

Setting: RANDOMIZED-QUICKSORT on $n$ distinct elements; rename them $z_1<z_2<\cdots<z_n$ and write $Z_{ij}=\{z_i,z_{i+1},\dots,z_j\}$. Let $X$ be the total number of element comparisons performed inside all PARTITION calls.

Lemma 7.1 (formulation) The running time of QUICKSORT is $O(n+X)$: PARTITION is invoked at most $n$ times (each call removes one element — the pivot — from further consideration), and each call does $O(1)$ work plus a number of comparisons that it contributes to $X$.
Lemma 7.2 (formulation) Distinct elements $z_i$ and $z_j$, $i<j$, are compared at most once, and $$\Pr[\,z_i\text{ is compared with }z_j\,]=\frac{2}{j-i+1}.$$

Why: elements are only ever compared to a pivot. Consider the first moment some element of $Z_{ij}$ is chosen as pivot. If that pivot is strictly between $z_i$ and $z_j$, the two are separated into different sides and never compared. If it is $z_i$ or $z_j$, they are compared (once — the pivot then leaves all future calls). Each of the $j-i+1$ elements of $Z_{ij}$ is equally likely to be that first pivot, so the probability is $2/(j-i+1)$.

Lemma 7.3 (formulation) $\;\mathbb{E}[X]=O(n\lg n)$.

Why: with indicator variables $X_{ij}=\mathbf{1}\{z_i \text{ compared with } z_j\}$, linearity of expectation and Lemma 7.2 give $$\mathbb{E}[X]=\sum_{i=1}^{n-1}\sum_{j=i+1}^{n}\frac{2}{j-i+1} =\sum_{i=1}^{n-1}\sum_{k=1}^{n-i}\frac{2}{k+1} \;<\;\sum_{i=1}^{n-1}2H_n=O(n\lg n),$$ where $H_n=\sum_{m=1}^n 1/m=\ln n+O(1)$ is the harmonic number.

Theorem 7.4 The expected running time of RANDOMIZED-QUICKSORT on $n$ distinct elements is $O(n\lg n)$.

Proof. By Lemma 7.1 the running time is $O(n+X)$; taking expectations and applying Lemma 7.3, $\mathbb{E}[\text{time}]=O(n+\mathbb{E}[X])=O(n+n\lg n)=O(n\lg n)$. $\blacksquare$

Exam tip The exam phrasing ("including the formulation of Lemmas 7.1–7.3") means: state all three lemmas precisely, prove 7.2 and 7.3 (the two-endpoints argument and the harmonic double sum), then Theorem 7.4 is one line. Practice the change of summation variable $k=j-i$.

⑥ Theorem 8.1 — the comparison-sort lower bound

Main idea Any comparison sort is a binary decision tree that must distinguish all $n!$ input orders. A binary tree with $n!$ leaves has height $\ge\lg(n!)=\Omega(n\lg n)$.

The decision-tree model (the "preceding discussion" the professor flags): a comparison sort gathers information about the input only by comparing pairs of elements. Its execution on inputs of size $n$ is modelled by a binary decision tree: each internal node is a comparison $a_i\le a_j$ (left subtree = yes, right = no), each leaf is the permutation the algorithm outputs. One run of the algorithm = one root-to-leaf path; worst-case number of comparisons = the tree's height $h$.

Theorem 8.1 Any comparison sort algorithm requires $\Omega(n\lg n)$ comparisons in the worst case.

Proof. A correct algorithm must be able to output every one of the $n!$ orderings of $n$ (distinct) elements — each permutation must appear as a reachable leaf, else there is an input the algorithm sorts wrongly. A binary tree of height $h$ has at most $2^h$ leaves, so $$2^h\;\ge\;n!\quad\Longrightarrow\quad h\;\ge\;\lg(n!).$$ Finally $\lg(n!)=\sum_{k=1}^{n}\lg k\ \ge\ \sum_{k=\lceil n/2\rceil}^{n}\lg k\ \ge\ \frac n2\lg\frac n2=\Omega(n\lg n)$ (equivalently, Stirling gives $\lg(n!)=n\lg n-n\lg e+O(\lg n)$). Hence $h=\Omega(n\lg n)$. $\blacksquare$

Corollary 8.2. Heapsort and merge sort, at $O(n\lg n)$, are asymptotically optimal comparison sorts. (And counting sort, radix sort, bucket sort beat the bound only because they are not comparison sorts.)

Exam tip Three marks live here: (1) define the model — the algorithm learns only via pairwise comparisons; (2) the counting step $2^h\ge n!$ with the correctness justification (every permutation must be a reachable leaf); (3) the estimate $\lg(n!)=\Omega(n\lg n)$ — know one of the two derivations cold.

⑦ Theorem 9.2 — RANDOMIZED-SELECT runs in expected linear time

Main idea Unlike quicksort, selection recurses into only one side. The random pivot's rank is uniform, so the recursive subproblem has expected size $\approx 3n/4$ — and $n+\frac34 n+\left(\frac34\right)^2 n+\cdots$ is geometric $=O(n)$. Formalized by substitution.

RANDOMIZED-SELECT$(A,p,r,i)$ finds the $i$-th smallest of $A[p..r]$: pick a random pivot, PARTITION (cost $\Theta(m)$ on an $m$-element subarray), then recurse into the single side containing the answer.

Theorem 9.2 On $n$ distinct elements, RANDOMIZED-SELECT has expected running time $\Theta(n)$ (regardless of which order statistic $i$ is requested).

Proof. The pivot is equally likely to have each rank $k\in\{1,\dots,n\}$. If the pivot has rank $k$, the recursion continues in a subarray of size at most $\max(k-1,\,n-k)$ — in the worst case the answer is always in the larger side. Writing $T(n)$ for the expected time, $$T(n)\;\le\;\frac1n\sum_{k=1}^{n}T\big(\max(k-1,n-k)\big)+O(n)\;\le\;\frac2n\sum_{k=\lfloor n/2\rfloor}^{n-1}T(k)+O(n),$$ since each size $k\ge\lfloor n/2\rfloor$ appears at most twice among the values $\max(k-1,n-k)$.

Now the substitution method: guess $T(k)\le ck$ for all $k<n$ (some constant $c>0$ to be fixed), and let $an$ bound the $O(n)$ term. Then $$T(n)\;\le\;\frac{2c}{n}\sum_{k=\lfloor n/2\rfloor}^{n-1}k+an \;\le\;\frac{2c}{n}\cdot\frac{3n^2}{8}+an \;=\;\frac{3c}{4}\,n+an,$$ using $\sum_{k=\lfloor n/2\rfloor}^{n-1}k\le\frac12\big((n-1)n-(\tfrac n2-1)\tfrac n2\big)\le\frac{3}{8}n^2$. Choosing $c\ge 4a$ makes $\frac{3c}{4}n+an\le cn$, completing the induction, so $T(n)=O(n)$. The bound is tight: just reading the input costs $\Omega(n)$. $\blacksquare$

Exam tip The two things graders look for: the recurrence with the $\max(k-1,n-k)$ term and the factor $2/n$, and a clean substitution step ending in "choose $c\ge 4a$". Contrast in one sentence with quicksort (recursing into both sides costs the extra $\lg n$).

⑧ Theorems 11.2 & 11.8 — the hashing bounds

Main idea Chaining: the expected chain length is the load factor $\alpha=n/m$, so search costs $\Theta(1+\alpha)$. Open addressing: each extra probe succeeds with probability $\ge 1-\alpha$, giving the geometric bound $\frac{1}{1-\alpha}$; averaging it over insertion history gives the $\frac1\alpha\ln\frac{1}{1-\alpha}$ successful-search bound.

Chaining

Hash table with $m$ slots, $n$ stored keys, collisions resolved by (doubly linked) chains; load factor $\alpha=n/m$. Assume simple uniform hashing: each key is equally likely to hash into each slot, independently.

Theorem 11.1 (formulation) An unsuccessful search takes expected time $\Theta(1+\alpha)$: computing $h(k)$ is $O(1)$ and the searched slot's chain has expected length $\alpha$.
Theorem 11.2 With chaining and simple uniform hashing, a successful search also takes average-case time $\Theta(1+\alpha)$, averaged over the $n$ stored keys being sought with equal probability.

Proof. New keys are inserted at the head of their chain. So when we later search (successfully) for a key $x$, the elements we examine are: $x$ itself, plus exactly those keys that collided with $x$ and were inserted after $x$. Let $x_1,\dots,x_n$ be the keys in insertion order and $X_{ij}=\mathbf{1}\{h(x_i)=h(x_j)\}$; simple uniform hashing gives $\mathbb{E}[X_{ij}]=1/m$ for $i\ne j$. The expected number of elements examined, for a uniformly random target $x_i$, is $$\frac1n\sum_{i=1}^{n}\Big(1+\sum_{j=i+1}^{n}\mathbb{E}[X_{ij}]\Big) =1+\frac{1}{nm}\sum_{i=1}^{n}(n-i) =1+\frac{1}{nm}\cdot\frac{n(n-1)}{2} =1+\frac{\alpha}{2}-\frac{\alpha}{2n}.$$ Adding $O(1)$ for computing the hash, the total is $\Theta(1+\alpha)$. $\blacksquare$

Open addressing

All elements live in the table itself ($\alpha=n/m\le 1$); a search follows the key's probe sequence $h(k,0),h(k,1),\dots$ until it finds the key or an empty slot. Assume uniform hashing — the probe sequence is equally likely to be any permutation of the slots — and no deletions.

Theorem 11.6 (formulation) With $\alpha<1$, the expected number of probes in an unsuccessful search is at most $\dfrac{1}{1-\alpha}$. (Each successive probe hits an occupied slot with probability $\le\alpha$, so the number of probes is dominated by a geometric distribution: $\sum_{i\ge0}\alpha^i=\frac{1}{1-\alpha}$.) Consequently (Cor. 11.7) an insertion also takes $\le\frac{1}{1-\alpha}$ expected probes.
Theorem 11.8 With uniform hashing, $\alpha<1$ and no deletions, the expected number of probes in a successful search is at most $$\frac{1}{\alpha}\,\ln\frac{1}{1-\alpha}.$$

Proof. Searching for a stored key $k$ retraces exactly the probe sequence followed when $k$ was inserted. If $k$ was the $(i+1)$-st key inserted ($i=0,\dots,n-1$), the table held $i$ keys at that moment, so by Theorem 11.6/Cor. 11.7 the insertion — and hence the later search — takes at most $\frac{1}{1-i/m}=\frac{m}{m-i}$ expected probes. Averaging over the $n$ stored keys, each equally likely to be the target: $$\frac1n\sum_{i=0}^{n-1}\frac{m}{m-i} =\frac{m}{n}\sum_{i=0}^{n-1}\frac{1}{m-i} =\frac1\alpha\sum_{k=m-n+1}^{m}\frac1k \;\le\;\frac1\alpha\int_{m-n}^{m}\frac{dx}{x} =\frac1\alpha\ln\frac{m}{m-n} =\frac1\alpha\ln\frac{1}{1-\alpha}. \;\blacksquare$$

Exam tip Sanity-check the formulas at $\alpha=0.5$: chaining $\approx 1.25$ probes; open addressing unsuccessful $=2$, successful $=2\ln 2\approx 1.39$. Quoting these shows the grader you own the result. Know the harmonic-sum-to-integral bound — it recurs across the course.

⑨ Theorem 15.1 — the greedy choice for activity selection

Main idea An exchange argument: any optimal solution can be modified — swap its earliest-finishing activity for the globally earliest-finishing one — without shrinking it. So "grab the earliest finisher" is always safe.

Setting: activities $a_1,\dots,a_n$ with start/finish times $s_i<f_i$; two activities are compatible if their intervals $[s_i,f_i)$ don't overlap. Sought: a maximum-size subset of mutually compatible activities. Let $S_k$ denote the subproblem "activities that start after $a_k$ finishes".

Theorem 15.1 Consider any nonempty subproblem $S_k$, and let $a_m$ be an activity in $S_k$ with the earliest finish time. Then $a_m$ is included in some maximum-size subset of mutually compatible activities of $S_k$.

Proof. Let $A_k$ be a maximum-size subset of mutually compatible activities of $S_k$, and let $a_j$ be the activity of $A_k$ with the earliest finish time. If $a_j=a_m$, we are done. Otherwise form $$A_k'=\big(A_k\setminus\{a_j\}\big)\cup\{a_m\}.$$ The activities of $A_k\setminus\{a_j\}$ are mutually compatible and each starts no earlier than $f_j$ (they are compatible with $a_j$ and finish after it). Since $a_m$ has the earliest finish time in $S_k$ and $a_j\in S_k$, we have $f_m\le f_j$ — so every activity of $A_k\setminus\{a_j\}$ starts at or after $f_j\ge f_m$, i.e. is compatible with $a_m$. Hence $A_k'$ is a set of mutually compatible activities with $|A_k'|=|A_k|$, so it is also maximum-size, and it contains $a_m$. $\blacksquare$

Exam tip This is the model "greedy-choice" exchange argument — the same skeleton as Huffman's Lemma 15.2. If asked about the elements of the greedy method: greedy-choice property (a locally optimal choice is consistent with some global optimum) + optimal substructure.

⑩ Huffman optimality — Lemmas 15.2, 15.3 & Theorem 15.4 EXAM 1 · 8 pts

Main idea (15.2) Exchange: sinking the two rarest characters to the deepest level never increases cost. (15.3) Substitution: merging them into one pseudo-character changes total cost by exactly $x.freq+y.freq$, so optimal for the merged alphabet ⟺ optimal for the original. Induction does the rest.

Prefix-free code ⟷ full binary tree $T$, characters at leaves, codeword length $=$ depth $d_T(c)$, cost $B(T)=\sum_{c\in C}c.freq\cdot d_T(c)$.

Lemma 15.2 — greedy choice If $x,y$ are two characters of lowest frequency, some optimal tree has $x$ and $y$ as sibling leaves at maximum depth.

Proof core: in any optimal $T$, take deepest siblings $a,b$; exchanging $x\leftrightarrow a$ changes the cost by $-(a.freq-x.freq)(d_T(a)-d_T(x))\le 0$ — a product of two nonnegative factors — and likewise for $y\leftrightarrow b$. The result is still optimal and has the desired shape.

Lemma 15.3 — optimal substructure With $z$ a new character, $z.freq=x.freq+y.freq$, and $C'=(C\setminus\{x,y\})\cup\{z\}$: if $T'$ is optimal for $C'$, then $T$ — obtained by expanding leaf $z$ into an internal node with children $x,y$ — is optimal for $C$.

Proof core: the cost bookkeeping $B(T)=B(T')+x.freq+y.freq$ (both $x$ and $y$ sit one level below where $z$ was). If some $S$ beat $T$, normalize $S$ by Lemma 15.2 to have $x,y$ as siblings, contract them into $z$, and get a tree for $C'$ cheaper than $T'$ — contradiction.

Theorem 15.4 HUFFMAN produces an optimal prefix-free code.

Proof: induction on $|C|$; the first merge is safe by Lemma 15.2, the recursive solution is optimal by induction, and expanding it back is optimal by Lemma 15.3. $\blacksquare$

⑪ Theorem 17.2 — augmenting red-black trees

Main idea If an extra per-node attribute is computable from the node and its two children alone, then insertions and deletions can maintain it for free (asymptotically): changes only propagate upward along one $O(\lg n)$ path, and each rotation is repaired locally in $O(1)$.
Theorem 17.2 — augmentation theorem Let $f$ be an attribute that augments each node $x$ of a red-black tree of $n$ nodes, and suppose $f(x)$ can be computed in $O(1)$ time using only the information in $x$, $x.left$ and $x.right$ — including $f(x.left)$ and $f(x.right)$. Then we can maintain the values of $f$ in all nodes during insertion and deletion without asymptotically affecting the $O(\lg n)$ performance of these operations.

Proof. The key observation: changing $f$ at a node $x$ can invalidate $f$ only at ancestors of $x$ — nothing outside the root-to-$x$ path depends on it. So after any structural change we walk upward from the lowest modified node, recomputing $f$ in $O(1)$ per node; the path has length $O(\lg n)$.

  • Insertion. Phase 1 (BST descent) attaches a new leaf $z$: recompute $f$ on the path from $z$ to the root, $O(\lg n)$. Phase 2 (fixup) performs recolorings — which don't affect $f$ — and at most 2 rotations. A rotation is a local rearrangement of two nodes and three subtrees; only those two nodes' $f$-values can change, and they are recomputed bottom-up in $O(1)$ from their (unchanged) subtrees, plus the $O(\lg n)$ upward path already being updated. Total: $O(\lg n)$.
  • Deletion. Same structure: the splice-out modifies the tree along one path (update $O(\lg n)$), and the delete-fixup performs recolorings plus at most 3 rotations, each repaired in $O(1)$. Total: $O(\lg n)$. $\blacksquare$

Canonical application — order-statistic trees: augment each node with $x.size=x.left.size+x.right.size+1$ (which satisfies the theorem's hypothesis). Then OS-SELECT (find the $i$-th smallest) and OS-RANK run in $O(\lg n)$, and inserts/deletes stay $O(\lg n)$.
